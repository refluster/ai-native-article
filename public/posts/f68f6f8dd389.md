## Executive Summary

2026年初頭のAnthropicは、約50日間でClaude Opus 4.6、Claude Sonnet 4.6、Claude Cowork、Claude Dispatch、Claude Code Security、Responsible Scaling Policyの更新を相次いで投入し、Claudeを「より賢い会話AI」ではなく「自律的に仕事を進める存在」へ押し進めた。出典記事が示す論点は、モデル性能の向上そのものより、CoworkとDispatchを軸に、AIがアプリをまたいで実務を処理する構成へ移った点にある。

## Claude Coworkが引き起こした「SaaSpocalypse」

Anthropicの2026年1月以降の更新は、単なるモデル改良から、日常業務の中心にClaudeを置く方向へ切り替わったと記事は描く。その転換点として位置づけられているのがClaude Coworkである。

- エビデンス
- 2026年1月、AnthropicはClaude Cowork向けのbusiness pluginsをresearch previewとして導入した。
- Coworkは「simple chat window」ではなく、desktop-style workspaceとして設計された。
- 記事によれば、Coworkは以下を可能にした。
- AI sessions across contextの保持
- multi-step workflowsの管理
- 提案ではなくfinished outputの生成
- Anthropicは、Coworkの一部がClaude itselfの支援で開発されたと説明した。
- 2026年2月初旬、Coworkはlegal, finance, HR, sales, and operations向けのspecialised AI pluginsへ拡張された。
- これにより、ユーザーはタスク完了のためにdifferent appsを行き来する必要がなくなったとされる。
- 記事は、この更新が伝統的SaaS企業のビジネスモデルへの疑義を投資家とソフトウェア企業に生じさせたと述べる。
- その市場反応として、Global software and IT service stocksに売りが広がり、報道ベースでnearly $285 billionの時価総額がa single trading sessionで失われた。
- この出来事は業界内で“SaaSpocalypse”と呼ばれ始めた。
- 結論
- 出典記事におけるCoworkの意味は、AI機能の追加ではなく、業務実行のインターフェースを「アプリ群」から「単一AIエージェント」へ寄せた点にある。
- 「SaaSpocalypse」はモデル精度の話ではなく、software along with large teams to operate itという既存SaaS前提に対し、a single AI agent can handle the work of several people at onceという構図が市場で織り込まれたことを示している。
## Opus 4.6 / Sonnet 4.6 / Claude Code Securityが示した「長時間・長文脈・コードベース全体」への拡張

Coworkの直後、Anthropicはモデル本体とコード向け機能を連続して更新した。記事は、これらを「複雑な仕事を継続して処理できる」方向の強化として整理している。

- エビデンス
- Coworkの投入から数日以内に、AnthropicはClaude Opus 4.6を「its most advanced AI agent model」として公開した。
- Opus 4.6には以下の特徴があると記事は述べる。
- a one-million-token context window
- longer task completion times
- large documents, codebases, or datasetsに対して、for hours without losing coherenceで自律的に作業可能
- adaptive reasoningにより、タスクに必要な計算量をモデル自身が判断し、manual settingsに依存しない
- 続いてAnthropicはClaude Sonnet 4.6を投入した。
- Sonnet 4.6は、より日常利用向けのモデルとして位置づけられ、以下が挙げられている。
- Opus 4.6に近いlong-context capabilities
- coding and workflow automationでの性能向上
- 記事によれば、Sonnet 4.6は開発者の間で急速に普及し、college studentsの雇用不安も引き起こした。
- 同時期にAnthropicはClaude Code Securityも拡張した。
- Claude Code Securityは、単純なパターン照合ではなくreasoningを用いてentire codebasesをレビューするツールとして説明されている。
- これにより、開発者が見落とす可能性のあるbugs, vulnerabilities, or errorsを検出・分析できるとされた。
- 結論
- 出典記事の整理では、Opus 4.6とSonnet 4.6は「高性能モデルの新バージョン」ではなく、長文脈と長時間の一貫作業を前提にしたエージェント化の基盤である。
- Claude Code Securityまで含めると、Anthropicは「コードを書くモデル」と「コード全体を検査するシステム」を同時に差し出しており、ソフトウェア開発の単一工程ではなく、工程全体への介入を狙っている構図になる。
## NASAのPerseverance実験からDispatchまで――「書けるAI」から「実行するAI」への移行

記事は、Claudeの進化を2026年だけでなく、2025年後半からの流れとして描いている。NASA実験はその先行例であり、Dispatchはその一般化された到達点として扱われている。

- エビデンス
- 2025年11月、AnthropicはClaude Opus 4.5を公開し、stronger coding and workplace featuresと“infinite chats” that removed context window limitsを打ち出した。
- 同時期、ClaudeはNASAの実験でPerseverance rover on Marsの経路計画支援に使われた。
- 実験では、NASAのエンジニアがClaude Codeを使い、high-resolution images from the Mars Reconnaissance Orbiterとterrain dataを分析した。
- その後Claudeは、ローバー誘導に人間のドライバーが使うのと同じ形式であるRover Markup Language (RML)の指示を生成した。
- 記事は、このNASAでの利用はnot meant for everyday usersだったが、AIがチャットボットを超えてreal-world tasksを扱えることを早期に示した事例だと位置づける。
- そして2026年3月時点での最大の一手として、AnthropicはClaude Dispatchを投入した。
- Dispatchはmobile and desktop useの間を橋渡しする機能として説明されている。
- ユーザーは移動中にtheir phoneからコマンドを送り、Claudeがtheir home or office computer上でタスクを実行できる。
- 具体例として記事が挙げるのは以下である。
- pulling local files
- editing spreadsheets
- running tools
- sending messages through desktop apps
- Dispatchの中核はlocally through Claude Codeで動作し、これにより企業導入を遅らせていたprivacy concernsの多くを回避するとされる。
- 記事は、DispatchによってAIをめぐる問いが「what the model could write or generate」から「what the model can actually do」へ移ったと述べる。
- 結論
- NASA実験とDispatchは、どちらもClaudeを「対話相手」ではなく「指示を受けて現実の作業系を動かす存在」として示している。
- とくにDispatchは、ローカルPC上のファイル、表計算、デスクトップアプリにまたがる操作を対象にしており、生成物の品質評価よりも、実行権限・環境接続・プライバシー配慮が中心論点へ移ったことを示している。
## Responsible Scaling Policyの変更と、Claude自身を使った開発高速化

記事は、Anthropicの更新ラッシュを支えた要因として、競争圧力だけでなく、Claudeを使ってClaudeを開発する循環にも触れている。同時に、安全性ポリシーの変更は、その加速を制度面で支えるものとして描かれている。

- エビデンス
- Anthropicは、創業以来、AI競争における比較的慎重なプレイヤーとして、自社をsafety and responsible development重視で位置づけてきた。
- しかし同社は、以前のフレームワークの一部がrestrictiveになっており、競争の加速下でリリースを遅らせていると認めた。
- そのためAnthropicはResponsible Scaling Policyを更新した。
- 新方針の下でも、同社はsafety and risk reportsの公開を継続するとした一方、powerful modelsを、testing and safeguards continue in parallelの状態でより柔軟に公開できるようにした。
- 記事はまた、AnthropicのエンジニアがClaudeを用いて以下を行っていると紹介する。
- write new code
- test features
- summarise changes
- この結果、開発サイクルを短縮し、更新をより速く出せるようになっているとされる。
- 記事全体のまとめとして、Anthropicは約fifty daysで、Claudeを「simply improving a chatbot」から「something closer to a virtual employee」へ進めたと記述する。
- その内訳として、記事は次の整理を示す。
- Cowork replaces apps
- Opus and Sonnet showed it could handle complex tasks
- Dispatch proved it could act on its own
- 結論
- 出典記事の立て付けでは、Responsible Scaling Policyの変更は安全性放棄ではなく、公開と検証を逐次並行化するための運用変更として説明されている。
- さらに、Claudeを開発そのものに使うことで、Anthropicは「AI製品を作る会社」から「AIが開発速度を押し上げる会社」へ移っており、今回の更新密度自体が製品機能の一部として作用している。
