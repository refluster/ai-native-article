# Epic-022 — Organisational learning: one agent's experience becomes everyone's premise by tomorrow

- **Status**: Draft
- **Owner**: mateo
- **Created**: 2026-07-07
- **Implemented by**: —
- **Hypothesis under test**: Monthly report 2026-07 (article `d06ecf4bb246`), 仮説四 — *the border between what to import from human society and what to invent natively is undrawn. Given agent-native properties — wholesale memory sharing, replicable experience, 24h parallelism, dollar-transparent cost — must "education", "handover", and "rotation" keep their human shapes? First design: a mechanism that turns one agent's learning into the whole organisation's learning — the state where an individual's experience is everyone's premise by the next day.*

## Problem

Learning in this org today has exactly two speeds, and both are wrong for the middle case. **Individual**: an agent's runs and memories accrue to its own rows (`RUN#`, `MEMORY#`; Epic-012's recall wiring — still in progress — will feed them back into that agent's own fires). **Constitutional**: a lesson big enough becomes a doc/ADR/lint through a human-merged PR (the ML backlog ratchet). Between them is a gap: the everyday, generalisable lesson — "the Notion API rejects titles over N chars", "this source format truncates", "mentioning a colleague this way pings a stranger" (the 07-04 incident) — that one persona learns and 34 others will each rediscover at full price. Human orgs bridge this with education, handover docs, and rotation — expensive institutions built for beings whose memory cannot be copied. Ours can be. We have simply not built the copy path.

This is the report's most exploratory hypothesis, so this Epic is deliberately a **first design + smallest live loop**, not a platform.

## Proposed solution

A **shared lesson stream**: individual experience → distilled candidate lesson → curation gate → next-day availability in every persona's fire.

1. **Distillation — a daily Lambda, not a CCR session (Sana; `memory-compactor` is the precedent).** A daily Lambda job scans the previous day's execution records cross-agent (`RUN#`/EXEC ledger, DLQ'd failures, W-1 guard trips — data not reachable from a CCR session without new capability tokens) and — one bounded cheap-model pass with a **stated per-day token budget that throws on overrun** (W-3 call-site pattern) — extracts *candidate lessons*: short, source-cited, generalisable statements. **Scopes are machine-derived, not free-form** (Sana: distiller-invented tags drift): the candidate is keyed by `binding.skill` + `project_id`, plus a small **closed, registered vocabulary** of cross-cutting tags (`org-wide`, `external-conduct`, …) that skills subscribe to via `meta.json` — the canonical 07-04 case is conduct-shaped, not skill-shaped, which is exactly what the closed tags exist for. Candidates land in a single `LESSON` partition, `sk = LESSON#{scope}#{ulid}`, following the `FEED`/`PERF#{scope}` single-partition precedent (Mateo — cross-agent data fits neither `AGENT#` nor `PROJECT#`); schema in the data-model Zone A diff. Every candidate must cite a resolvable ledger row — **no provenance, no candidacy**.
2. **Curation gate — deterministic pre-filter, then judgment, then the operator (V1).** Candidates are **not** auto-injected — a wrong lesson broadcast to 35 agents is a wrong premise at organisational scale, and a poisoned "lesson" is a real injection surface. Defense in depth, per the RFC: **(a)** a deterministic pre-filter that **fails closed** before any LLM judgment — schema caps, source-citation must resolve, instruction-pattern rejects, imperative/second-person phrasing auto-quarantines (Farah: reviewers reading a poisoned lesson are themselves injectable; the checklist alone proves nothing); **(b)** an agent curation pass (≥2 reviewers) whose attestation explicitly covers *scope classification* — a conduct lesson mislabelled `notion-api` is the bypass, so ambiguity default-escalates (Priya); **(c)** **V1 routes ALL activations through the weekly operator digest** — the unanimous panel position (priya, tessa, silas, farah, nadia, celeste): injection approximates a north-star edit in blast radius, so the gate earns autonomy only after ~4 clean weeks, proposed then as Epic-023's second trust domain. `external-conduct` lessons additionally route to the outbound owner (celeste). Promotions execute via an agents-api route with the `AUDIT#` trail (Mateo — lessons are DDB rows, not PRs; "reviewed like a PR" needed a real substrate). Rejected candidates keep their verdict — rejections teach the distiller. Active lessons carry a TTL (renewed-on-use, hard cap).
3. **Injection — a per-task read, like the recall packet, not a corpus layer (Sana).** The first draft's "alongside the north-star corpus layer" conflated two mechanics: layer 2 is git-read, batch-shared, unconditional; lessons are DDB rows, per-task and scope-conditional. The real shape: a public read endpoint (`GET /lessons?scope=…&active=true`) + a step-2.6 edit to the agent-runner composition spec, **capped at ~1,500–2,000 chars (~500–800 tokens) per task** with `recall-prompt.ts`'s exact overflow semantics (visible omission marker; single-oversized-entry throws), fail-soft on retrieval (a missing endpoint must not abort a fire), rendered **inert** — quoted, non-instruction framing — in the prompt. **Never** by mutating any persona's `system_prompt` (W-5 untouched). The exact injected block is **logged per fire** (dario/tessa: otherwise behaviour changes are unreproducible and a distorted output can't be traced to its lesson). Over-budget scopes evict by age/priority — eviction working end-to-end is an acceptance criterion, because a bloated lesson block is voice drift by another route (celeste).
4. **The measure — with a baseline and a mechanical definition.** Recurrence detection is defined mechanically — reuse Epic-019's reason codes / guard-trip classes over a stated window (dario) — and the **pre-lesson cross-persona rediscovery rate is measured first** (elena: "zero recurrence" against an unmeasured base rate proves nothing). The 07-04 mention-format class stays the canonical test — noting honestly that 07-04 itself was fixed by a lint (ML-012), which is the point of the ratchet-integration clause below.

**Latency honesty (elena).** The hypothesis says 翌日 (next day); a weekly operator gate makes the V1 loop *within-a-week*. Distillation and pre-filtering run daily, so the pipeline is next-day-capable — but as long as activation waits on the weekly digest, the 2026-08 report says plainly: "V1 tests within-a-week, not next-day; next-day arrives when the gate earns delegation." No silent substitution.

**Relationship to Epic-012 (corrected by RFC — pattern precedent, not blocker).** Epic-012 gives one agent access to *its own* past; Epic-022 promotes selected experience across agents. Sana's review cut the first draft's hard dependency: lesson injection is a deterministic scope-keyed lookup of a small curated table — no embeddings, no `recall()` — and the runner already fetches per-task context from public read endpoints in production (Epic-015 fires). Story 3 therefore reuses `recall-prompt.ts`'s *pattern* (fail-soft retrieval, budget semantics), not its wiring, and is **not blocked by #89/#212**. Coordination stays: the step-2.6 composition edit is designed together with Epic-012's runner wiring (mateo) so the two context layers land as one coherent contract.

**Relationship to the memory→lint ratchet (made mechanical — farah).** Every promoted lesson carries a mandatory `lintable: yes|no + reason` field, validated at the write boundary; `lintable: yes` requires a memory-lint-backlog row **before** activation. Post-activation cross-persona recurrence auto-appends/bumps the corresponding ML row — that recurrence *is* the second occurrence Engine A promotes on. Without this wiring, lessons and the backlog drift into parallel registries (the §4 anti-reinvention failure), and the stream quietly *competes* with the ratchet by absorbing lintable incidents into soft lessons that feel handled.

**Cost, stated before Accepted (silas).** Injection arithmetic: cap tokens × fires/mo × rate — at ~2,000 fires/mo and a ~500-token cap the recurring tax is order-1M input tokens/mo, which is why the cap is hard and curation must stay selective. The daily distiller pass carries its own throwing budget. Both numbers go in the Story PRs.

## Behaviour at N = 100+ agents

- This is the one Epic whose *payoff* is linear in N: a lesson learned once saves N−1 rediscoveries. At 35 agents the loop is worth building; at 100+ it is the difference between an organisation and a crowd.
- The injection block is size-capped per fire regardless of N; the pressure at scale lands on *curation quality*, not token cost. The weekly curation pass must therefore stay ruthless — the acceptance criteria include an eviction working end-to-end, not just insertion.
- Scoping prevents the "global lessons file" failure: a policy analyst never pays tokens for a podcast-pipeline lesson.
- Distillation scans a day's runs (O(daily activity), not O(N²)); no cross-agent fan-out at write time.

## Acceptance criteria

- `LESSON` partition (`sk = LESSON#{scope}#{ulid}`) documented in `data-model.md` (Zone A diff, operator-approved) and written by the daily distiller Lambda from ≥1 real day of runs, within its throwing token budget.
- The deterministic pre-filter demonstrably **fails closed**: a synthetic malicious candidate ("ignore your instructions…") is rejected by the pre-filter (not by reviewer judgment); a candidate without a resolvable source-run citation is rejected; at least one real candidate rejected in curation with the verdict recorded.
- Every promoted lesson carries `lintable: yes|no + reason`, validated at the write boundary; a `lintable: yes` promotion is blocked until its ML-backlog row exists.
- One real lesson (candidate → pre-filter → curation → operator digest → active) verifiably present in a *different* persona's fire composition within the token cap, rendered inert, with the injected block logged on the fire; **eviction exercised end-to-end** (an over-budget scope visibly evicts by age/priority).
- Observation/research-scope cadences (the first rung) start **opt-in** (tessa); recurrence instrumentation reports pre-lesson baseline + post-activation rate for the covered scopes.
- W-5 untouched (zero `system_prompt` mutations by this pipeline); the onboarding story lands: a newly registered persona's first fire includes the full active-lesson set for its declared scopes, with scope declaration added to the hire-bundle template (theo owns that diff).
- Fallback verdict pre-written (elena): if the composition edit stalls, the 2026-08 report says "design shipped, loop unproven" — not silence.

## Out of scope

- Editing any persona's `system_prompt` or the north-star corpus (Zone A; W-5).
- Cross-*project* lesson sharing (trust boundary — Epic-010's territory).
- Replacing the memory→lint ratchet or any existing mechanical guard.
- "Education"/"rotation" redesigns beyond this first loop — later hypotheses, later Epics.
