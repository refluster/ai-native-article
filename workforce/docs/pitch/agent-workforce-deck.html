01The structural shift

The minimum unit of capability moves from a person to an execution

In a human organization, holding a capability in-house means employing at least one person who has it. Salary, benefits, hiring, training, management and a continuous supply of work all apply even when the actual workload is a fraction of a headcount. So capabilities whose expected return does not clear one full employment cost get outsourced — or never get done at all.

A network of software talent changes the arithmetic. Capability runs per task, per hour, per workflow: idle when there is no work, duplicated when demand spikes, retired when it is not needed. The result is not simply cheaper labor.

It lowers the value threshold at which a piece of work is worth doing at all — the third category, the work that was never staffed and never outsourced, becomes executable.

Variable cost without losing the capability

Outsourcing makes human capability variable by moving it outside the company — the learning leaves with the vendor. Here the procedures, judgment criteria, evaluations and execution history stay in-house while only the running cost tracks activity.

The asset is the harness, not the model

Foundation models commoditize. What compounds is the harness around them: business context, proprietary data, procedures, tools, permissions, evaluation criteria, audit trail, execution history.

Compounding, not one-off savings

Buying the same deliverable more cheaply pays once. A harness that improves on every run raises capability and speed on every subsequent run, across every project connected to it.

02System structure

One substrate, many roles

Every agent runs on the same substrate. Work enters through governed entrypoints, context is composed at run time from the project, the skill and the agent, deliverables leave through deterministic writers holding project-scoped credentials, and every run lands in the observability and track-record layer.

03The composition model

Projects × Skills × Agents

Three axes, defined independently and combined at run time. This separation is where the scalability actually comes from — each axis can grow without re-doing the other two.

PROJECT

Where — the scope and the authority

Target repository or publication surface, the governance documents that apply, the credential types available, the owning role and reviewer roster. Permissions are bounded per project; nothing crosses.

SKILL

What — the executable job procedure

A self-contained definition of input, judgment, deliverable shape and destination. Whoever runs it produces the same class of result. Scheduled ones are Cadences — recurring work that no human has to file.

AGENT

Who — the professional and their history

A job description, a position in the org, an identity with operating principles, long-term memory, an activity record, and a set of assignments. Judgment lives here; procedure does not.

Capacity ≈ projects × skills × agents
Add a role → one definition; it can run all 41 existing skills on day one
Add a skill → one definition; 57 candidate practitioners already exist
Add a project → one definition plus credentials; the whole organization can staff it

In a human organization, hiring, writing procedure and winning work are three separate costs that do not multiply. Separating the axes is what makes them multiply here.

04Anatomy of an agent

What an agent is made of

An agent is not a prompt. It is a durable professional record — the same components a company keeps for an employee, plus the ones only software can keep.

JD & MISSION

What they are here to change

A one-line mission, key responsibilities, and success measures written to be judged against. Example: a Chief of Staff whose mission is to manage the operator's attention, measured by attention consumed per week falling while decisions made per week does not.

POSITION

Where they sit

Reporting line, lateral partners, desk membership, and the streams they are accountable for. The org chart is data, not a picture — routing and escalation read from it.

IDENTITY

How they decide

An archetype and explicit operating principles — the lens they bring to a review, the tie-breakers they use, the things they refuse to do. This is what makes a panel of agents produce different findings instead of the same one four times.

LONG-TERM MEMORY

What they have learned

Durable notes carried between runs, curated on a schedule and swept org-wide for contradictions and staleness — so a conclusion from March is either still true in August or explicitly retired.

ACTIVITY RECORD

What they have actually done

An engagement ledger of runs and deliverables: what shipped, on which project, reviewed by whom. Performance and skill maturity are computed from it, not asserted.

FEED

What they publish to the org

Each agent posts to a shared activity feed — findings, hand-offs, digests. This is how one desk's learning reaches another desk's next execution without a meeting.

ASSIGNMENTS

What they are on the hook for

Bindings of (agent × skill × project) on a cadence — every six hours, daily, weekly, monthly. Work arrives on schedule; nobody dispatches it.

RESOURCES

What they are allowed to spend

A pinned model per role, a monthly budget, a prompt version, and the credential types their project grants them. Cost and blast radius are bounded per agent.

EVALUATION

How their output is judged

Deliverables are scored against per-level rubrics by judges with distinct perspectives — editor, domain, reader — and the chosen candidate's prompt version travels with the published work.

09Control

An organization that does not run away

Adding agents multiplies both output and failure modes. Governance was built before capability: a constitution, framework law, mechanical regulation and operational runbooks, each harder to change than the one below it.

Four inviolable principles

Editorial integrity — nothing empty, truncated or model-failure-tainted reaches a reader. A single source of truth. No primitives beyond single-operator scale. Fail loud: a broken state throws rather than publishing a degraded result.

Mechanical gates

Truncation and empty-body detection at publish time, corpus gates at deploy time, CI checks on the registry itself. Enforcement is machinery, not judgment.

Explicit authority split

What an agent may execute, and what requires the human: merging, changing the default branch, amending governing documents, prompts or rubrics, spending beyond the envelope.

Recurrence ratchet

A failure mode that recurs within 90 days is automatically promoted from a note to a mechanical check. The organization tightens itself.

Independent adversarial review

A red-team role hunts for weaknesses on its own cadence, outside the delivery line that produced the work.

Multi-candidate, multi-judge quality

Several generators produce candidates; several judges score them against a rubric; the chosen candidate's prompt version is published with the work so reader behavior can be attributed back to it.

The same design answers the obvious objection to connected organizational memory: a network that propagates learning also propagates error. Provenance, confidence, applicability conditions, independent evaluation and correction history are part of the record, not an afterthought.

10Economics

What this changes for management

The case is not that software labor is cheaper than people. It is that the set of capabilities a company can economically hold — and connect — gets larger.

The ROI floor drops

Work whose value never justified one full-time hire, and was too small to outsource, becomes executable: continuous competitive monitoring, cross-project failure-pattern extraction, low-frequency legal and standards analysis, per-customer follow-up, post-project surveillance.

Capability stays in-house while cost stays variable

Outsourcing moves the learning to the vendor. Here the harness, evaluations, execution history and customer context remain internal; only the run cost tracks activity.

A network effect that is computational, not social

Human knowledge sharing costs attention, search, explanation and translation, and coordination paths grow as n(n−1)/2. Here one execution's learning is mechanically available to the next relevant execution — without every agent talking to every other.

The cost of staying aligned falls

Collecting cross-functional information, detecting contradictions between plans and assumptions, analyzing the blast radius of a change and confirming it landed everywhere are what made enterprise-wide alignment an annual event. When those costs fall, alignment becomes continuous work embedded in operations.

Local autonomy is preserved, not centralized

The gain is not deciding everything centrally. It is leaving authority at the edge while surfacing inconsistency with the whole early enough to correct it.

Try the business before staffing it

Instead of assembling specialists, operations and vendor contracts before a new line is tested, capability is composed as a harness and people and capital are added where customer evidence appears.

Competitive advantage does not sit in model access — models commoditize.
