Agent Workforce — 会社紹介 / Pitch

人を増やさずに、
組織を増やす。

Agent Workforce は、意思決定者が人間ひとりのまま、専門職エージェント × 業務スキル × プロジェクトの三層で運営される、実働中のAIオペレーション組織です。記事・レポート・PR・Podcast・規制分析まで、成果物が毎日出続けています。

57登録エージェント（職種別ペルソナ）
41スキル（実行可能な業務手順）
5稼働プロジェクト
1人間の意思決定者

数値は本リポジトリの登録実体（workforce/seed, workforce/skills, workforce/projects）から機械的に数えたもの。

01問題設定

「AIを使う」は増えた。「AIが業務を回す」はまだない。

多くの現場のAI活用は、人間が都度プロンプトを打つ単発作業です。担当も、手順も、成果物の品質基準も、責任の所在も、人間の頭の中にしかありません。そのため使う人が増えるほど、レビュー負荷という形で人間側がボトルネックになります。

担当がいない

誰の仕事かが定義されず、専門性が蓄積しない。同じ調査を毎回ゼロから。

手順が残らない

うまくいったプロンプトが個人のチャット履歴に埋もれ、再現も改善もできない。

品質が保証されない

途中で切れた文章、空の出力、幻覚がそのまま外に出る。止める仕組みがない。

02解法の骨格

エージェント × スキル × プロジェクト

この三層の分離が、Agent Workforce のスケーラビリティの本体です。「誰が（人格・専門性・判断基準）」「何を（再現可能な業務手順）」「どこで（対象・権限・認証情報）」を独立に定義し、実行時に合成します。

AGENT

誰が — 専門職ペルソナ

職務記述（ミッション／責務／成功指標）、判断原則、所属・レポートライン、月次予算、記憶を持つ。人間の組織図と同じ粒度で採用・配置される。

SKILL

何を — 実行可能な業務手順

「入力・判断の型・成果物・書き込み先」を明文化した自己完結フォルダ。誰が実行しても同じ品質で同じ形の成果物が出る。定期実行されるものを Cadence と呼ぶ。

PROJECT

どこで — 対象と権限

対象リポジトリ、適用されるガバナンス文書、使える認証情報の種類を束ねる単位。プロジェクト単位で権限が絞られ、越境できない。

出力可能な業務 ＝ エージェント(57) × スキル(41) × プロジェクト(5)
新規エージェント追加コスト ＝ 定義ファイル1件（既存スキル全部を即座に実行可能）
新規プロジェクト追加コスト ＝ 定義ファイル1件＋認証情報（既存の職種全員が即座に担当可能）

人間組織では「人を採る」「手順を作る」「案件を取る」が全て別コストで、しかも掛け算になりません。三層を分離したことで、どの軸を伸ばしても残り二軸の資産がそのまま乗ります。

07品質保証

暴走しない組織設計

エージェントを増やすほど、事故確率は上がります。だからこの組織は、能力より先に統治を作りました。憲法 → 法律 → 規制（自動チェック）→ 執行ルールの四層で、上位ほど変更が難しくなっています。

絶対に破れない4原則

編集の誠実性（空記事・途中で切れた文章・LLM失敗の痕跡を世に出さない）／唯一の情報源を定める／単一運用者スケールを超える機能を作らない／壊れたら黙って続けず必ず落とす。

機械的に止まるゲート

公開前の切断検知、成果物の空/短文検知、CIの各種ゲート。違反したら公開されずビルドが赤くなる——判断ではなく仕組みで止める。

権限の線引き

自動実行してよい領域と、人間の承認が必須の領域（マージ、本番ブランチへの直接変更、統治文書・プロンプト・評価基準の改定、予算枠外の支出）が明文化されている。

再発防止ラチェット

同じ失敗が90日以内に2回起きたら、運用上の注意ではなく自動チェックへ自動昇格。組織が自分で締まっていく。

敵対的レビュー

Red Team ロールが「あえて弱点を探す」レビューを独立に回し、監査は執行ラインの外に置かれている。

多候補・多審査の品質層

記事生成は「1プロンプト1記事」ではなく、複数の生成者が書き、複数の審査者（編集/専門/読者の視点）がルーブリックで採点して採用案を決める。採点は読者行動と突き合わせて外側のループに戻る。

08実行基盤

どう動いているか

スケジューラがティックを打ち、オーケストレータが「エージェント × スキル × プロジェクト」の文脈を合成してランナーに渡す。成果物は決定論的な書き込みスクリプトが、プロジェクト単位の認証情報で所定の宛先にPOSTする。人間はダッシュボードで見て、上がってきた判断だけを下す。

  • トリガ — スケジュールイベントがオーケストレータを起動。各スキルのケイデンス（毎日／6時間ごと／週次／月次）で発火。
  • 文脈合成 — ペルソナ定義＋スキル手順＋プロジェクト設定＋その人の記憶を組み立ててエージェント実行環境へ。
  • 書き込み — 生成物はLLMが直接publishせず、バンドルされた書き込みスクリプト経由。ここに編集ガードが実装されている。
  • 可視化 — 社内コンソールに組織図・活動記録・レポート、公開面はWebサイト・GitHub・Discord/Slack・Podcast配信。
  • 記憶 — 各メンバーの知見が記録・整理され、組織全体の記憶の矛盾・陳腐化が定期点検される。
09拡張性

どこまで伸ばせるか

今の構成は5プロジェクト・41スキル・57ペルソナですが、増分コストの形が普通の組織と違います。

職種を足す

定義ファイル1件で新しい専門職が入社し、その瞬間に既存41スキル全てを実行できる。教育期間ゼロ。

業務を足す

スキルを1つ書けば、57人全員の候補担当者がいる状態で始まる。実行者を探す工程が存在しない。

案件を足す

プロジェクト定義と認証情報を登録すれば、組織まるごとがその案件を担当できる。立ち上げは人月ではなく設定。

この形が効く先は、「専門性の高い調査・監視・文書生産が、恒常的に発生し続ける」領域です。規制ウォッチ、市場リサーチ、投資家向けレポーティング、社内ドキュメント運用、コードベースの継続的な保守。いずれも、人間ひとりが常時見張るには重すぎ、外注するには文脈が失われすぎる領域です。
