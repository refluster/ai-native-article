## 与件 (熟議の到達点を与件として固定する)

熟議4ラウンドの結論は **すべて「実測のない設計上の仮説」** と自己申告されている。本調査の仕事は、それらを外部の一次・準一次資料で検証し、**支持 / 一部支持 / 不支持 / 未検証** の判定を付けて返すことである。熟議で確立した到達点:

| # | 熟議の到達点 (仮説) | 提出者 |
|---|---|---|
| D1 | IT部門は「エージェントを作る人」ではなく、エージェントが動く**共通基盤と境界線を預かる側**。業務エージェントは現場が作ってよい | mateo, 全員 |
| D2 | 最初の一歩は**一つのチームが黙って払っている迂回コスト** (シャドーAI・個人契約ツール・手作業の転記) を、一作業単位で、そのチームの言葉で置き換えること。全社基盤から売らない | yuki, anjali |
| D3 | 権限の線 (Zone-A・お金・マージは人間へ)、監査ログ、「提案/出荷」の語彙は、最初のチームと**同時に**基盤へ入れる (売る順と敷く順は別) | mateo, freya |
| D4 | 成果 (迂回コスト、meaningful-work ratio、影のエージェント数) は IT部門の自己採点ではなく**第三者 (監査・財務)** が数える | anjali |
| D5 | 投資の重心は a) 基盤 (権限・セキュリティ・監査可能性)。b) 事業部門がワンクリックで調達できる「歴戦の傭兵」は**後段**。昇格単位は個体ではなく**第三者が数えた実績のある一作業 (スキル)**。二つ目の部門が自費で採用した後にだけ横展開する | 全員 (R3) |
| D6 | 個体の「育成」は、記憶圧縮後も**同一性**が保たれることを確認してから。リコールパケットの形は a) の仕事 | freya |
| D7 | 機密情報は「守るか開くか」ではなく、**資産の等級 + 三段階アクセス台帳 (読むだけ / 要約して下書き / 外部へ出す) + 最小権限シークレットと失効手順 + 監査ログ**を先行投資し、制度改訂の日に段階を動かせる状態にする | mateo, anjali (R4) |
| D8 | 台帳は全資産を一度に分類せず、最初の一チームが実際にAIへ貼り付けている情報から埋める。各段階は台帳の行ではなく「作業の完了条件」として現場の言葉で書く | yuki, freya |
| D9 | モデルのコモディティ化後、IT部門の役割は「機密の番人」から「**自社資産をどの接続面でどの条件で外と結ぶかの設計者**」へ移る。公開情報 vs 固有資産の価値は比較実験で第三者が決める | mateo, anjali |

反証条件 (熟議が自ら置いたもの): 基盤整備後も影のエージェントが減らない / 最初のチームが個人契約に戻る / 完了件数だけ増えて meaningful-work ratio が上がらない / 選べるチームが見つからない / 台帳が形骸化する / 段階を細かくした後に no-op 比率が上がる / 昇格したスキルが二つ目の部門で再利用されない / 再利用のコストが基盤コストを上回る。

## 読み手と「この調査は元が取れた」と言える条件

- 読み手: 企業IT部門 (CIO / 情報システム部長 / AI推進担当)、および熟議の参加ペルソナと operator。
- 元が取れた条件 (margaux の「三条件」):
  1. 熟議の9つの到達点それぞれに、外部証拠にもとづく判定と確度が付く (G8 verdict floor)。
  2. 未解決点 U1–U11 のうち少なくとも半数に、外部実務での「解き方」の事例か、解けない理由が示される。
  3. 読み手が次の四半期に打てる **投資の順序と反証条件の期限** が、図1枚で言い直せる。
- kill line: 外部に一次・準一次資料が40件未満しか集まらない場合は、調査を「仮説整理」に格下げして納品し、限界章に明記する。
