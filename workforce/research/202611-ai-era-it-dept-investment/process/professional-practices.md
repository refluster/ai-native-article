# Professional research practices — reference for a 12-stage gated study

Internal reference (English). Compiled 2026-11-04 for the study `202611-ai-era-it-dept-investment`.
Purpose: show how professional research and advisory organisations design and quality-gate a study, so the workforce's stage-gate process can borrow from documented practice. It is not meant to invent new process.

## How to read the verification marks

Every claim carries one of these marks. They refer to the source list (P-n) at the end.

| Mark | Meaning |
|---|---|
| **[V]** | Verified. The primary page or PDF was fetched and read on 2026-11-04. Short quotes are copied from that text. |
| **[S]** | The official URL was found, but the fetch was blocked (HTTP 403/503 or a host block). The content comes from the search engine's index snippet of that official page. Re-read the page before quoting it in the final report. |
| **[2nd]** | Only secondary sources were found (books summarised by others, blogs, vendor reprints). Use the idea, but do not attribute it as an official definition. |

## 2. Design implications for a 12-stage gated study

Each stage lists: the practice it borrows from (row numbers above), and the concrete **gate criterion** that must pass before the next stage starts. Gate outcomes follow Stage-Gate (row 32): **Go / Kill / Hold / Recycle**, and every Go names the next gate date and owner.

General rule from Stage-Gate and Forrester: deliverables and criteria for **every** gate are written at the Brief stage. Later gates check against them. They are not renegotiated mid-study. The Forrester rule that "criteria, scales, and weightings are a matter of opinion" settled before scoring, while scores are about facts, maps directly onto this.

### S1 Brief
- **From:** RAND kickoff application of the standards (23); Cochrane pre-specified PICO and protocol (27); Gartner "Scenarios" step, which sets the objective by question (1); Stage-Gate deliverables defined in advance (32); Minto SCQ (20).
- **Gate criteria:**
  1. One governing question, written as an SCQ (Situation, Complication, Question) and phrased so it can be answered.
  2. Scope as a PICO-like spec: population (which IT departments: size, industry, region), intervention (investment category), comparator, outcomes, time horizon.
  3. Named decision-maker and the decision the study informs (ICD 203 tradecraft 5: customer relevance; RAND Relevance and Engagement).
  4. Deliverables, criteria and reviewers for all 12 gates listed (Stage-Gate).
  5. Conflict-of-interest and independence statement: no vendor-funded conclusions; sponsor cannot buy the conclusion (Gartner 10, Forrester 15, RAND Legitimacy).

### S2 Issue tree
- **From:** McKinsey logic trees and MECE (18, 19); ICD 203 analysis of alternatives (24.4); ACH (26).
- **Gate criteria:**
  1. The tree is MECE at every level, checked by a reviewer who did not build it.
  2. Every leaf is a falsifiable hypothesis or question, with the evidence that would confirm or refute it.
  3. At least one competing hypothesis is recorded for each major branch (ACH: "identify all the reasonable alternative hypotheses").
  4. A **Key Assumptions Check** is logged: an assumptions list with "what if wrong". The Primer says this is "most useful at the beginning".
  5. A Day-1 answer is written down as the hypothesis to beat. [2nd practice]

### S3 Workplan
- **From:** McKinsey prioritise → workplan (18); Anthropic effort scaling (31); Stage-Gate outputs = resources + next-gate date (32).
- **Gate criteria:**
  1. The tree is pruned. Each kept leaf maps to an analysis, a source type, an owner (persona) and a due gate.
  2. Effort budget declared per leaf. Anthropic tiers are a useful template: simple = 1 agent / 3–10 tool calls; comparison = 2–4 agents; complex = 10+.
  3. Cost estimate fits the budget (W-3 ledger). "No approval without resources."
  4. Ghost deck / storyline skeleton drafted: action titles per section, data still blank. [2nd]

### S4 Fact pack (evidence collection)
- **From:** Anthropic "start wide, then narrow" (31); Gartner Surveys + Pattern Recognition (1); ICD 203 all-sources + source quality (24.d, 24.1); Primer Quality of Information Check (26); Cochrane eligibility criteria (27); PRISMA flow (29).
- **Gate criteria:**
  1. Every fact has a source ID, URL, publisher, date and access date. Primary is preferred, and the tier is marked (primary / secondary / vendor-sponsored).
  2. Inclusion and exclusion of sources follows the S1 criteria, with a PRISMA-style count: found → screened → excluded (with reason) → used.
  3. A source summary statement names the strongest and weakest sources behind each key judgment (ICD 203 / ICD 206).
  4. Known information gaps are listed explicitly (ICD 203 standard d).
  5. Vendor-supplied figures are flagged as such. They cannot be the only support for a key judgment.

### S5 Analysis
- **From:** ACH matrix (26); GRADE certainty rating (28); ICD 203 tradecraft 2, 3 (24); Gartner "Stalking Horse" (1); Critical Capabilities use-case weighting (4); IDC Capabilities vs Strategy horizons (16).
- **Gate criteria:**
  1. Each S2 hypothesis has an evidence matrix (consistent / inconsistent / N/A). Conclusions come from what is **disconfirmed**, not from tallying support.
  2. Each key finding has a GRADE-like certainty rating (high / moderate / low / very low) with stated downgrade reasons (risk of bias, inconsistency, indirectness, imprecision, publication / vendor bias). Ideally two independent raters reconcile (MECIR C74).
  3. Information, assumptions and judgments are labelled separately (ICD 203 tradecraft 3).
  4. If a scoring framework is used (for example, rating investment options), criteria, scales and weights are frozen **before** options are scored (Forrester; Gartner CC refresh rule).
  5. The working position is circulated to the other analyst personas as a "stalking horse" and debated.

### S6 Storyline
- **From:** Minto Pyramid / SCQ (20); ICD 203 tradecraft 6, "clear main analytic message up front" (24); ghost deck (21).
- **Gate criteria:**
  1. One governing answer at the top. Every section heading is a full-sentence claim that its children summarise (vertical logic). Sibling claims are MECE (horizontal logic).
  2. Each claim traces to S5 findings with their certainty level. No orphan claims.
  3. "So what" test per section: each section ends with the implication for the decision-maker. (Practice label not found in a primary source; the substance is ICD 203 tradecraft 5, "addresses implications".)
  4. Pre-wiring list: who must see the headline before the panel. [2nd]

### S7 Draft
- **From:** ICD 203 likelihood scale and confidence rule (25); ICD tradecraft 7, 8, 9 (24); Gartner / IDC prediction phrasing (8, 17); IDC FutureScape driver → impact → guidance template (17).
- **Gate criteria:**
  1. Every forward-looking statement uses one fixed vocabulary, for example the ICD 203 seven-term scale (Japanese equivalents fixed once in a glossary), plus a time horizon: "By 2028, …".
  2. A sentence never carries both a likelihood term and a confidence level (ICD 203 rule (b)).
  3. Each prediction / recommendation block states associated drivers, impact on the IT department, and guidance (FutureScape template).
  4. Indicators or signposts: for each major judgment, what observable event would change it (ICD tradecraft 3, 4; Primer "Indicators").
  5. Change versus prior work is stated where it applies (ICD tradecraft 7).
  6. Visuals pass the "clarify, don't decorate" bar (ICD tradecraft 9).

### S8 Fact-check
- **From:** New Yorker independent checking (30); Anthropic CitationAgent as a separate step (31); Forrester vendor verification of facts, and the facts vs opinion split (13, 14); Gartner vendor factual review (2).
- **Gate criteria:**
  1. A checker persona that did **not** write the draft checks every factual sentence against its cited source and records a per-claim verdict (supported / partially / unsupported / source unreachable).
  2. Quotes and numbers are matched character-for-character to the source. Units, dates and denominators are checked.
  3. Unsupported claims are cut or downgraded. They are never "softened" without a source.
  4. Disputes are logged and settled by writer + editor, with the checker's evidence on record (New Yorker practice [2nd]).
  5. Facts only. Disagreement about framing or weighting goes to S9, not here (Forrester rule).
  6. Pass threshold: 0 unsupported key claims; 100% of numbers traced.

### S9 Panel review + red team
- **From:** Gartner peer review by analysts outside the document + consensus-or-discard (1, 2); Forrester research-director review of all scores (13); RAND independent peer review (23); Primer Devil's Advocacy, Team A/Team B, High-Impact/Low-Probability, Red Team (26); ICD 203 Objective standard (24.a).
- **Gate criteria:**
  1. At least 2 independent reviewers who are not authors: at least one domain reviewer and one methods reviewer. Each scores against the RAND six pillars, or against ICD 203's nine tradecraft standards as a rubric.
  2. A **Devil's Advocate** writes the strongest case against the governing answer. Authors respond in writing.
  3. A **Red Team** argues from inside the decision-maker's or affected party's position. For this study: a skeptical CFO, a vendor, the IT operations team. This matches the Primer's adversary-perspective definition.
  4. A **High-Impact/Low-Probability** pass names at least one tail scenario that would invalidate the recommendations.
  5. A Key Assumptions **recheck** ("prior to finalizing judgments").
  6. Outcome: consensus, or the contested position is dropped or downgraded (Gartner "consensus or the position is discarded").

### S10 Revision
- **From:** Forrester feedback-then-final-verification loop (13); Stage-Gate Recycle (32); Cochrane documentation of every downgrade (28).
- **Gate criteria:**
  1. Every panel, red-team and fact-check comment has a disposition (accepted / rejected with reason / deferred), recorded in a response log.
  2. Changed claims go back through S8 for that delta only.
  3. Certainty labels are updated where evidence changed.
  4. Gate decision Go / Recycle (back to S5 or S6) / Kill.

### S11 Build (layout, figures, publish artefacts)
- **From:** Forrester courtesy-preview freeze, "no new information or escalation" (13); ICD tradecraft 9 visuals (24).
- **Gate criteria:**
  1. Content freeze. Only typo or layout fixes after this gate. Any substantive change sends the work back to S10.
  2. Every figure has a source line and data file. Numbers in figures match the text.
  3. Both editions (ja/en) match in claims and numbers (W-1/W-2 analogue).
  4. Mechanical checks green (truncation, links, citations resolve).

### S12 Delivery + retro
- **From:** Forrester "correct material errors quickly" (15); ICD 203 annual evaluation against the standards and the accuracy standard (24.8); Stage-Gate post-launch review (32); IDC / Gartner predictions later graded (third-party trackers exist [2nd]).
- **Gate criteria:**
  1. Published with a methodology note (sources count, PRISMA-style flow, certainty legend, likelihood scale, reviewers) and a corrections policy.
  2. Prediction register: every dated prediction is logged with its likelihood term and horizon, so it can be scored later (accuracy loop).
  3. Retro records which gate caught which defect, and which defects escaped. Escapes feed the memory-lint backlog.
  4. Post-publication errors are corrected visibly with a dated note.

### Cross-cutting rules
- **Independence:** no sponsor or vendor influence over conclusions. The reviewers are not the authors, and the checker is not the writer (Gartner, Forrester, RAND, ICD 203).
- **Separation of roles:** lead / orchestrator, researchers, analyst, writer, checker, panel, devil's advocate / red team, gatekeeper (Anthropic, Forrester, Stage-Gate).
- **Fixed vocabularies:** likelihood scale (ICD 203), certainty scale (GRADE), maturity phases (Hype Cycle, if used, with Gartner's phase names credited and not redefined).
- **Facts vs opinion:** facts are disputed at S8 and opinions at S9 (Forrester).
