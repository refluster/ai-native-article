工程

約 40 名の AI ペルソナで一冊の本を分業するための工程表です。出版社が企画会議から校了までに積み上げてきた段取りを読み、AI の組織でもそのまま効くものを十のステージと十のゲートに置き直しました。台割、構成編集と原稿整理の分離、執筆者から独立した校閲、赤字の照合、校了の署名がそれにあたります。初号は Web book『孫子の兵法』です。

読み方。この文書は、出版社の実務を参照して設計した、約 40 名の AI ペルソナで分業する工程の説明です。まず一枚の工程図（01）で全体をつかみ、出版社の二つの伝統（02）、ステージとゲートの中身（03）、誰が何を担うか（04）、古典を出すときの決まり（05）、初号『孫子の兵法』での実行（06）の順に読んでください。根拠にした資料は 07 にあります。実行の手順そのものはセッション skill book-production に書いてあり、ここは人が工程を確かめるための説明書です。ペルソナが仕事を受け取る仕組みはホワイトペーパーにあります。

01Process map

工程図

工程は上下二段で読みます。上の段で、何を、どの順で、何字で書くかを決め、骨格を固めます。下の段で、文と事実と権利を整えてから公開します。段と段のあいだには必ずゲートがあり、通らなければ次へ進みません。

ゲートの合否は二種類の方法で出します。一つは機械判定で、スキーマ、字数、引用の一致、文の長さ、リンク、色のトークン、赤字の反映といった、数えれば決まることを owen が検査に書き、farah が CI で回します。もう一つは判断レビューで、企画の価値、底本の選び方、構成、声、初学者に分かるか、主張が反証に耐えるか、権利の境界、図解が正しいか、そして最後の校了を、役割を持つペルソナが判断します。

機械で決まることを人の目に任せず、人の判断が要ることを機械の合格で済ませない。この区別がこの工程の骨組みです。新しい検査はまず警告として入れ、同じ種類の指摘が 90 日以内に二度出たらゲートに格上げします（組織全体の memory → lint の手順と同じです）。

02Two traditions

出版社はどう作るか

工程は発明していません。日本の新書・文庫の作り方と、英語圏の一般書・学術書の作り方を読み比べ、AI の組織で崩れやすいところを補う側を選んで組み合わせました。

日本の書籍は、企画会議から始まります。編集者が仮タイトル、読者、目次案、類書との差、判型・頁数・定価を企画書にまとめ、会議で通れば著者と契約します。次に台割で頁の配分と展開を決めます。ある編集の手引きは「雑誌の編集とはこの台割作成を指すといってもよい」とまで書いています。取材と執筆、原稿整理、造本設計と組版を経てゲラが出ると、校閲が事実と表現の妥当性を調べ、校正が初校・再校・三校と原稿とゲラを照合します。最後に「校了」か「責了」で校正を終え、装丁と色校、印刷・製本（文藝春秋の例では校了から約 1 か月）、配本へ進みます。

英語圏では、編集が段階ごとに名前を持っています。企画を選ぶ acquisition（学術書では 2 名以上の査読と教員の Board の承認を経ます）、構成と論旨を直す developmental edit、文の質を整える line edit、文法・表記・相互参照を正す copyedit、そして雑誌に典型的な fact-checking です。Chicago は copyedit を「実質的な変更ができる最後の機会」と位置づけ、developmental edit は必ず最初に行うものとされます。後で消える章の文を磨いても無駄だからです。組版後の proofreading では、著者による直し（AA）と編集者による直し（EA）を区別して費用と責任を分けます。刊行の 4〜6 か月前には ARC（事前見本）を業界誌へ送ります。

日本 · 新書・文庫

独立した校閲と、明確な終点

  • 企画会議が入口。企画書に読者・目次案・類書・仕様を書く
  • 台割で頁配分を先に決める。強い設計の道具
  • 校閲は専門職・専門部署。執筆者から独立している
  • 校正は初校 → 再校 → 三校。前の校の赤字が入ったかを確かめる
  • 校了／責了という終点と、責任の所在がある
  • 弱点：原稿整理の中で構成と表記の直しが混ざりやすい
英語圏 · trade / academic

編集の段階に名前があり、順序が決まっている

  • Acquisition と、学術書では peer review・Board 承認
  • Developmental → line → copyedit の順。構成を先に固める
  • copyedit は実質的な変更の最後の機会（Chicago）
  • Fact-checking は雑誌で独立部署（New Yorker）。書籍では copyedit に含まれることが多い
  • proofreading で AA と EA を分け、費用と責任を区別する
  • ARC を 4〜6 か月前に配り、先行読者の声を集める

設計に持ち込んだ六つのこと

独立校閲

品質保証は、書いた人と別の人が持つ

日本型を採ります。事実・引用・権利を確かめる校閲（S6）を執筆者から切り離し、各章の校閲者はその章の執筆者と同じにしません。

構成 → 文

構成編集と原稿整理を別のゲートにする

英語圏の順序を採ります。構成編集（S4・G4）で骨格を確定してから、原稿整理（S5・G5）で文を磨きます。構成が確定するまで S5 以降には入りません。

企画会議

入口は社内の企画会議型

G0 は新書と同じ企画会議型にします。ただし第 I 部の訳注に限り、査読に相当する独立した読み（S6 の原文照合）を義務づけます。

校了

終点と責任の所在を書面にする

校了票に署名者を決め、責了で直してよい範囲（誰の責任で、何を直せるか）を明文化します。英語圏が AA と EA の区別で分けている費用と責任を、署名と範囲の規程で引き受けます。

先行読者

ARC は「先行公開章＋読者の声」

Web 書籍では、数章を限定公開して読者の声を集めることを ARC や献本に相当させます。集めた声は S7 の成果物として残します。

台割

頁ではなく、字数と読了時間で割る

台割は日本の出版に特有の強い道具です。Web には頁がないので、章ごとの字数予算と読了時間の予算（Reader と同じ 600 字/分で見積もります）として使います。

05Classics

古典を出すときの決まり

「原典に忠実」は、決めておかないと検査できません。岩波文庫『新訂 孫子』（金谷治訳注）の原文・読み下し・現代語訳・注・索引という構成を型として、何を守れば「忠実」かを操作的に定義しました。

底本

底本を一つ明示する

『孫子』には魏武注本、武経七書本、十一家注本、銀雀山竹簡本（1972 年出土）の系統があります。推奨は十一家注本系の通行本を本文とし、竹簡本との主要な異同は注で示すこと。最終判断は G1 で行います。形篇の攻守句に竹簡本で語順の逆転があるという広く知られた異同は、一次資料で未確認のため、sora が異同表の作業で検証します。

原文

原文は底本どおりに転記し、改変しない

旧字・異体字の扱いは表記規程に先に書きます。本文中の原文ブロックは、分節した原文と正規化後に完全一致しなければ G3 の引用 lint で落ちます。解説と第 II 部は原文の段落 ID を参照し、原文が言っていないことを原文の主張として書きません。

訓読

訓読は自前でつくる

慣用の読み（返り点・送り仮名の通例）に従うのは構いません。独自の読みを採るときは注で根拠を示します。他者の書き下しには独自の工夫が入っていれば保護されうるので、写さずに安全側を取ります。

現代語訳

クリーンルームで訳す

訳者は下訳のあいだ、他者の現代語訳を見ません。参照できるのは原文、辞書、注釈の語義だけで、何を参照したかを作業ログに残します。idris がログを抜き取りで監査します。補った語は〔 〕で示し、意訳の幅は規程で決めます。

名言

名言ボックスは原文＋訓読＋出典

名言ボックスには必ず原文・訓読・訳・篇名・段落 ID を並べます。流布している形が原文と違うときは「よく言われる形」として別に記し、誤りであることを明示します。たとえば謀攻篇の「百戦殆うからず」は「百戦百勝」と言い換えられがちです。

権利

原文はパブリックドメイン、他者の訳は二次的著作物

原文は二千年以上前の著作で、保護期間（原則、著作者の死後 70 年）を大きく過ぎています。一方、既刊の現代語訳は翻訳という二次的著作物として原作とは別に保護されるため、流用も下敷きも禁止です。他訳との比較を論じるときだけ、引用の 4 要件（公表済み・公正な慣行・正当な範囲・出所の明示）を満たす最小限を引きます。

06First run

初号『孫子の兵法』での実行

工程の計画は暦で約 9 週間です。初号では、それを運用者の 1 セッションに圧縮し、作業パッケージ（WP）ごとにサブエージェントを立てて並行に走らせます。圧縮するのは待ち時間だけで、ゲートの省略も順序の入れ替えもしません。

実行の形について。初号は運用者のセッションが司会する役割演技です。各 WP のサブエージェントは担当ペルソナの立場で書き、読み、判定しますが、ペルソナが binding から自律的に起動したわけではありません。校了票の署名と実績（engagement）の記録には、その旨を「operator-orchestrated」と明記します。機械ゲート（check-book と prebuild フック、名言集の生成）は Reader と同じ PR で repo に入り、それが main に載るまでは、この文書の記述は設計です。

本は二部構成です。第 I 部は 1 篇を 1 章とし、要旨、段落ごとの原文・訓読・訳・語注、解説、名言ボックス、図解 1 点の順に並べます。第 II 部は、始める前に勝敗を測る（計篇）から詭道の倫理（計篇・火攻篇）まで、篇の考え方を現代のプロジェクトと組織に当てて読む章です。

  1. リサーチパック（WP-10〜16）— 底本の確定、原文の分節と段落 ID、異同表、訓読 v1、名言候補、先行書の一覧、用語集、権利メモと開示文。最初の依存元なので先頭で済ませます。→ G1
  2. 台割と章設計書（WP-20）— 章ごとの字数予算、対応する原文 ID、図版枠、担当。→ G2
  3. 執筆を並行レーンで（WP-30a/b/c・WP-31）— 第 I 部を計〜形／勢〜九変／行軍〜用間の 3 レーンで、各レーン内は篇の順に。第 II 部は、対応する篇の初稿ができた章から着手します。→ G3
  4. 図版（WP-70）— 各篇 1 点と全体図の SVG、表紙。章設計書の図版枠を受けて、執筆と並行に描きます。
  5. レビューと lint（WP-40・50・60、検査の実装は WP-51 で前倒し）— 構成編集 → 原稿整理 → 校閲。少なくとも三つのレンズ（構成、可読性、事実と反証）で読みます。→ G4〜G6
  6. Reader でのビルドと校正（WP-71・80）— 3 層の切替、再開位置、章の残り時間を持つ読書画面でビルドし、初校・再校・三校を赤字台帳で回します。→ G7・G8
  7. PR — Reader、機械ゲート、本文を一つの PR にまとめ（工程ページと skill は別 PR）、レビューが合意でグリーンになれば workforce の pr-autopilot がマージします。
  8. デプロイと校了（WP-90）— 公開、live smoke、校了票への署名。以後は正誤表を運用します。→ G9
13 篇『孫子』の全篇。第 I 部で 1 篇 1 章
約 12 万字初号の本文（付録を除く実測 121,482 字）
22 章 + 付録序・導入・前編 13 篇とまとめ・後編 5 章・終章・名言集
≥ 3原稿ごとのレビューレンズ

字数と章数は初号の G3 時点の実測です。研究段階の台割案（総計約 12 万字、章設計書 21 本）を初号の範囲に合わせて詰め、付録の名言集は register から生成しています。書籍本文の正本を git に置くこと（記事本文の正本は Notion）は、ADR で明文化してから運用します。
