Software
Talent Network

A company no longer has to hire a whole person — or send the work outside — in order to hold a capability. It can encode that capability as a governed, executable, improving internal asset, and run it per engagement.

Definition. Software Talent Network is a software-defined operating organization of persistent AI professionals, governed by one human decision-maker. It is not a staffing service, a talent marketplace, or a recruiting product; no human labor is bought or sold through it.

01Executive summary

Capability as an internal asset, held per execution

In a human organization the minimum unit of capability is a person. Salary, benefits, hiring, management and a continuous supply of work apply even when the real workload is a fraction of a headcount, so any capability whose expected return does not clear one full employment cost is either sent outside or left undone. This document describes a running system in which the minimum unit is an execution instead.

The consequences that matter to management are stated here rather than at the end:

  • The ROI floor for holding a capability drops. Work too small to staff and too small to outsource — continuous competitive monitoring, cross-project failure-pattern extraction, low-frequency standards analysis, per-customer follow-up, post-project surveillance — becomes executable.
  • Run cost tracks activity; the capability does not leave. Outsourcing makes cost variable by moving the learning to a vendor. Here the procedures, judgment criteria, evaluations, permissions and execution history stay internal.
  • The asset is the harness, not the model. Foundation models commoditize. What compounds is business context, proprietary data, procedures, tool connections, permissions, evaluation criteria, audit trail and execution history.
  • Learning connects across projects under explicit conditions. One execution's evaluated learning becomes available to the next relevant execution, with provenance and applicability attached — not by having every agent talk to every other.
  • A business line can be executed before it is staffed. Capability is composed as a harness first; people and capital follow the evidence.

None of this claims zero marginal cost. Every run consumes model tokens, cloud resources, connector calls and — where authority requires it — human review time. The claim is narrower and more useful: the unit at which capability can be held, priced and improved is smaller than a person, while the learning stays inside the company.

Scope of evidence: this document distinguishes throughout between what is operating, what is partial, what is planned, and what is not yet measured. Counts are mechanically taken from the registry; they measure implementation scale, not business outcome.

02The thesis

An agent is not a prompt

The common failure in agent programs is to equate an agent with a model plus an instruction. That framing makes capability look like something you buy, and makes every improvement disappear as soon as the conversation ends. A persistent professional is a different object.

Capability = model + context + procedure + tools + permissions + evaluation + execution history

Each term is separately owned, separately versioned and separately improvable. The model is the one term the company does not own and cannot differentiate on for long. The remaining six are the harness — and the harness is what makes a given model produce this company's work rather than generic work.

Procedure is written down, not remembered

A skill defines input, judgment, deliverable shape and destination. Two different agents running it produce the same class of artefact; a change to it applies everywhere it is used.

Judgment belongs to the agent

Identity, operating principles and memory sit with the professional, not the procedure. This is why a review panel returns different findings instead of the same finding four times.

History is the compounding term

Runs, evaluations, corrections and reusable findings accumulate. A harness that improves on each run raises capability and speed on every subsequent run — a one-off cheaper deliverable does not.

A model change is therefore a component swap inside a stable structure, not a restart. Model choice is pinned per role and versioned alongside the prompt so that a quality shift can be attributed to a cause.

03The constraint

The organizational constraint being removed

When a capability is recognized as necessary, a human-centred organization resolves it in one of three ways: employ, outsource, or leave undone. The third branch is the largest and the least visible, and it is not a management failure — it was the rational response to the cost of holding a capability at all.

ResolutionConditionWhat the company keeps
EmployContinuous value above one full employment costCapability and learning, at fixed cost
OutsourceDeal-sized value, discontinuous demandDeliverables; the learning stays with the vendor
Leave undoneBelow both thresholdsNothing — the work does not exist
Encode as a harnessProcedure can be specified and its output evaluatedCapability, evaluations and history internally; run cost follows activity
The change is not that labor becomes cheaper. It is that the value threshold at which a piece of work is worth doing at all moves down — and the third branch starts producing.

Two qualifications keep this honest. First, human capability can also be made variable through contracting; the difference is where the learning ends up, not whether cost flexes. Second, generic capability — research, drafting, analysis, coding — is available immediately from a model, but company-specific capability is not: it requires data access, written judgment criteria, tool and permission wiring, an evaluation design and an escalation path. The accurate claim is that company-specific capability can be composed in far less time than hiring and training, not that it is instant.

05Composition

The composition model: projects × skills × agents

Three axes are defined independently and combined at run time. The separation is what lets one axis grow without redoing the other two.

PROJECT

Where — scope and authority

Target repository or publication surface, the governance documents that apply, the credential types available, the owning role and the reviewer roster. Credentials and project-specific authority are scoped to the project and do not cross it; evaluated learning can cross under the conditions in §08.

SKILL

What — the executable procedure

A self-contained definition of input, judgment, deliverable shape and destination, owned by a role. Scheduled skills are Cadences: recurring work that no human files. A skill carries its own writer, so the side effect is deterministic rather than model-generated.

AGENT

Who — the professional and their record

Job description, organizational position, identity and operating principles, long-term memory, activity record, assignments, resource limits, evaluation history. Judgment lives here; procedure does not.

What actually scales — and what does not

The naive reading of three axes is a product of three counts. That reading is wrong, and stating it precisely matters more than stating it impressively:

Addressable execution combinations scale with
compatible projects × qualified skills × eligible agents

Each qualifier is a real gate. A skill is qualified for a project when its deliverable type, destination and evaluation design fit that project's surface. An agent is eligible for a skill when the domain fits its job description, when its identity and memory make its judgment relevant, when its project grants the credentials the skill needs, and when its pinned model is adequate to the task. A project is compatible when its governance documents permit the class of side effect the skill produces.

Adding…What is genuinely reusedWhat still has to be established
A roleThe whole existing skill library is available to it without being rewritten.Domain fit per skill, execution eligibility, credential grants, and an evaluation baseline before its output is trusted.
A skillThe existing bench is a candidate pool; no hiring round is needed to find a practitioner.Which roles are actually qualified, the rubric it is judged against, and its destination and writer.
A projectRoles, procedures, governance patterns and the evaluation apparatus carry over.Scope, credentials, applicable governance documents, reviewer roster, and the deliverable destination.

In a human organization, hiring, writing procedure and winning work are three separate costs that do not compound. Here they do compound — but only across combinations that pass the qualification gates above. Combinatorial possibility is not validated capability; §12 keeps that distinction.

06Agent model

Anatomy of a persistent agent

An agent is a durable professional record: the components a company keeps for an employee, plus the components only software can keep. All of them are data, versioned in the registry and readable by the runtime.

JD & MISSION

What it is here to change

A one-line mission, key responsibilities and success measures written to be judged against. Example: a Chief of Staff whose mission is to manage the operator's attention, measured by attention consumed per week falling while decisions made per week does not.

POSITION

Where it sits

Reporting line, lateral partners, desk membership and accountable streams. The org chart is data, not a picture: routing and escalation read from it.

IDENTITY

How it decides

An archetype and explicit operating principles — the lens brought to a review, the tie-breakers used, the things refused. This is the mechanism behind perspective diversity on a panel.

LONG-TERM MEMORY

What it has learned

Durable notes carried between runs, curated on a schedule and swept org-wide for contradiction and staleness, so a conclusion from March is either still true in August or explicitly retired.

ACTIVITY RECORD

What it has actually done

An engagement ledger of runs and deliverables: what shipped, on which project, reviewed by whom. Performance and skill maturity are computed from it rather than asserted.

FEED

What it publishes to the organization

Findings, hand-offs and digests posted to a shared activity feed — the path by which one desk's learning reaches another desk's next execution without a meeting.

ASSIGNMENTS

What it is on the hook for

Bindings of (agent × skill × project) on a cadence — six-hourly, daily, weekly, monthly. Work arrives on schedule; nobody dispatches it.

RESOURCES

What it may spend

A monthly budget and bounded blast radius per agent, so a misbehaving cadence is capped in both cost and reach.

MODEL & PROMPT VERSION

What it runs on

A model pinned per role from a registry, plus a prompt version. Both travel with the output, so a change in quality can be attributed to a change in configuration.

CREDENTIALS

What it may reach

Credential types granted by the project it is running for, resolved at execution time and never held by the agent independently of a project context.

EVALUATION

How its output is judged

Deliverables scored against per-level rubrics by judges with distinct perspectives — editor, domain, reader — with the chosen candidate's prompt version published alongside the work so downstream behavior can be attributed back to it.

GOVERNING DOCS

What binds it

The governance documents named by its project, plus the organization-wide constitution. Authority limits are read from these, not from the agent's own judgment.

Anthropomorphism is a modelling convenience here, not a claim. "Job description", "identity" and "record" name data structures that make behavior consistent, attributable and improvable. Nothing in this document asserts that an agent has experience or interests of its own.

07Architecture

System architecture and execution flow

Every agent runs on one substrate. Work enters through governed entrypoints, context is composed per run, deliverables leave through deterministic writers holding project-scoped credentials, and every run lands in the track-record layer.

The lifecycle of one run

  1. Trigger. A schedule fires for a binding of (agent × skill × project), or a human or system event arrives at an entrypoint. Cadence frequency is part of the binding, not the skill.
  2. Context composition. The runtime assembles the agent's job description, identity and long-term memory; the skill's procedure; the project's scope, governance documents and credential grants; and the relevant slice of the feed.
  3. Execution. The composed context runs against the model pinned for that role, within that agent's budget.
  4. Deterministic write. The deliverable is not published by the model. A writer bundled with the skill posts it to the authenticated destination, and the editorial and integrity guards live in that writer — so a degraded result fails loudly instead of shipping.
  5. Evaluation. Where a generating lane uses the quality layer, candidates are scored against a rubric by multiple judges and one is chosen; the chosen prompt version travels with the published artefact.
  6. Recording. The run, its deliverable and its review lineage are written to the engagement ledger; memory and feed are updated for the next relevant execution.
  7. Escalation. Anything outside the agent's authority — a merge, a governing-document change, an external send, spend beyond the envelope — is packaged as a decision for the human rather than executed.

Two properties of this flow matter more than the components. Side effects are deterministic and guarded, so the model's variance cannot reach the outside world unchecked. And the composition step is what makes the same substrate serve every role: nothing in the runtime is bound to one project or one profession.

08Learning

Memory, learning and cross-project reuse

The organizational value of a network is that one execution's evaluated learning becomes available to the next relevant execution. That is a narrower and more defensible claim than "everything is shared", and it requires an explicit boundary between what may cross a project line and what may not.

AssetCrosses project boundaries?Condition
CredentialsNoResolved per project at run time; never held by an agent across contexts.
Confidential project dataNo, by defaultStays within the project surface unless an explicit, recorded grant says otherwise.
Project-specific authorityNoAuthority is granted by the project and does not travel with the agent.
Evaluated learning with provenanceConditionallyMay cross when source, date, confidence and applicability conditions travel with it — and when the differences that would invalidate the transfer are stated, not just the similarities.
Reusable skill improvementsYes, after reviewA procedure change propagates once evaluated and approved; it then applies wherever the skill is used.
Failure patterns & mechanical controlsYes, sanitizedConfidential specifics removed; the pattern and the check that catches it are organization-wide.
Agent performance historyYes, within permissionUsed organizationally for staffing and maturity assessment, under the same access rules as any other record.

Human knowledge sharing costs attention, search, explanation and translation, and coordination paths grow as n(n−1)/2 — which is why large organizations localize decisions rather than share everything. The mechanism here is different in kind: the learning is written in a common form and retrieved by the execution that needs it. The goal is not agents talking to each other at scale.

A network that propagates learning propagates error at the same speed. Provenance, confidence, applicability conditions, independent evaluation and correction history are part of the record, not an afterthought.

Operating per-agent memory curation and org-wide contradiction and staleness sweeps; the shared feed; sanitized failure patterns promoted into mechanical checks. Partial systematic tagging of confidence and applicability on every carried finding. Not yet measured how often a finding from one project measurably improved an execution on another — the reuse-rate metric in §13.

09Governance

Governance, authority and failure containment

Scaling agents multiplies output and failure modes together. The governance layer is therefore structural rather than advisory: four layers, each harder to change than the one below it, with enforcement in machinery wherever a rule can be made mechanical.

Operating

Constitution — four inviolable principles

Editorial integrity: nothing empty, truncated or model-failure-tainted reaches a reader. A single source of truth for content. No primitives beyond single-operator scale. Fail loud: a broken state throws rather than publishing a degraded result.

Operating

Framework law — decision records

Architectural decisions are recorded and superseded rather than edited in place, so the reasoning behind a constraint survives the person or agent that set it.

Operating

Mechanical regulation — gates

Truncation and empty-body detection at publish time, corpus gates at deploy time, registry checks in CI. A violation turns the build red or blocks the publish; it is not a warning.

Operating

Operational runbooks

What to do when a lane fails, how to localize a breakage between source, generation and deploy, and how to recover — written down rather than reconstructed under pressure.

Operating

Explicit authority split

Agents execute inside a defined envelope. Merging, changing the default branch, amending governing documents, prompts or rubrics, sending anything externally, and spending beyond the envelope require the human.

Operating

Recurrence ratchet

A failure mode that recurs within 90 days is promoted from a note to a mechanical check. Repeat incidents convert into controls instead of into folklore.

Operating

Independent adversarial review

A red-team role searches for weaknesses on its own cadence, structurally outside the delivery line that produced the work.

Partial

Multi-candidate, multi-judge evaluation

Several generators produce candidates; judges with distinct perspectives score them against a rubric; the chosen candidate's prompt version is published with the work. Applied on generating lanes today; extension to every lane is planned.

Operating

Project-scoped credentials

Credentials are resolved per project at run time and shipped into the run, so an agent's reach is bounded by the engagement it is executing.

Operating

Budget and blast-radius limits

Per-agent monthly budgets and bounded side effects cap the cost and the damage of a misbehaving cadence.

Partial

Accountability sweeps

Automated detection of stalled or unowned work with assignment to a responsible role; coverage is being extended across lanes.

Planned

Rubric-linked outcome attribution

Connecting evaluation scores to downstream reader and reviewer behavior, closing the loop from judgment to observed result.

Governance in this system was designed alongside the first delivery lanes and has been extended as lanes were added; several mechanisms — the ratchet and the deploy gates among them — exist because a specific failure occurred first. The honest statement is not that governance preceded capability everywhere, but that no lane is permitted to publish without a mechanical guard on its side effect.

11Economics

Management economics

The management case rests on which capabilities a company can economically hold and connect — not on labor arbitrage.

The ROI floor drops

Work that never justified a hire and was too small to outsource becomes executable: continuous competitive monitoring, cross-project failure-pattern extraction, low-frequency legal and standards analysis, per-customer follow-up, post-project surveillance.

Variable cost without losing capability

The harness, evaluations, execution history and customer context remain internal while run cost follows activity. Costs are real — model tokens, cloud, connectors, and the human review the authority split requires — but they scale with use rather than with headcount.

Compounding rather than one-off savings

Buying the same deliverable more cheaply pays once. A harness that improves each run raises capability on every subsequent run, wherever that skill is used.

A computational network effect

One execution's evaluated learning is retrievable by the next relevant execution, without the attention and translation costs that cap human knowledge sharing — and without requiring every agent to communicate with every other.

The cost of staying aligned falls

Collecting cross-functional information, detecting contradictions between plans and assumptions, analyzing a change's blast radius and confirming it landed everywhere are what made enterprise alignment an annual exercise. Lower those costs and alignment becomes continuous work embedded in operations.

Execute before you staff

Instead of assembling specialists, operations and vendor contracts before a line is tested, capability is composed as a harness and people and capital follow the evidence. The option value of a cheap, reversible trial is part of the return.

The more the network can align, the more explicitly leadership must state what to prioritize, whose interests to reconcile, and who is accountable.

Competitive advantage does not sit in model access. It sits in proprietary data, judgment criteria, tool connections, permissions, an evaluation system that separates success from failure, execution history, and the loop that redistributes one desk's learning into another's next run.

12Limits

Limitations, risks and open questions

The credibility of this design rests on its stated conditions of validity, not on breadth of claim. The following are unresolved, and several are structural rather than temporary.

Dependence on external providers

Model and cloud providers are single points of dependency for availability, price and behavior. Model changes can shift output quality without any change on our side; version pinning limits but does not remove this.

Domain onboarding is not instant

Generic capability is immediate; company-specific capability requires data access, written judgment criteria, tool and permission wiring, an evaluation design and an escalation path. That work is real and front-loaded.

Context, tooling and evaluation cost

The harness is the asset and also the expense. Rubrics, judges, guards and connectors take design effort, and a poorly designed evaluation is worse than none because it manufactures false confidence.

Purpose remains human

Objectives, priorities, exceptions, risk appetite and final accountability are not delegable. A system that lowers the cost of alignment raises, rather than lowers, the demand on leadership to state what it wants.

Political and P&L conflict is not automated away

The network can make amounts, beneficiaries and burdens visible. It cannot resolve conflicts that require changing P&L structure, incentives, authority or who absorbs a loss.

Shared learning can propagate error

Transfer between domains can be a false analogy that looks well-supported. Provenance, confidence, applicability and correction history mitigate this; systematic tagging is only partially implemented.

Agent count is not value

Registry scale says nothing about output quality or business result, and a larger roster increases coordination, evaluation and governance surface.

Possibility is not validated capability

Addressable combinations grow quickly; validated combinations grow only as fast as evaluation does. Treating the first number as capacity would be the central error of this model.

Quantitative evidence is missing

Cost, speed, quality trend and human-time metrics are not yet instrumented. Until they are, the case rests on structure and observable artefacts rather than on measured performance.

The single decision-maker is a bottleneck

One human owning purpose and consequence is a deliberate constraint at this scale. As lanes multiply, the escalation surface grows and the attention ledger becomes load-bearing; multi-operator authority is an unsolved design question here.
