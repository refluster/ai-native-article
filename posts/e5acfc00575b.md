## Executive Summary

X 上で「ショウ｜AI×個人開発×投資 時短ワーパパ」（@sho_ai_magic）が 2026年6月20日に公開した実践ガイド「SLIDE.md 実践ガイド｜インストールからスライド生成まで完全ガイド」は、Claude Design で生成するスライドの「毎回デザインがガチャのようにバラつく」問題を、SLIDE.md と呼ぶスライド専用デザインシステムで解消する手順を、インストールからスライド完成までの4ステップに分解して提示している。投稿はインプレッション 979,939、ブックマーク 4,508、いいね 1,383 を集めており、AI 生成スライドの一貫性（色・フォント・余白・構図の固定）が個人開発者の関心領域として成立していることを示す。中核の主張は明快で、デザインの再現性は生成時の指示力ではなく、生成前に外部化された設計書（SLIDE.md / SLIDE-PATTERN / SLIDE-DECK.md）に宿るという点にある。

## 解決しようとしている問題：生成物のバラつき

ガイドが冒頭で立てる問題提起は、評価軸そのものに踏み込んでいる。著者は「Claude Designでハイクオリティなスライドが爆速で作れる時代になりました。ただし、毎回デザインがガチャのようにバラつくのが最大の悩みでした」と述べる。

ここでの論点は速度ではなく一貫性である。生成スピードは既に解決済みの前提とされ、未解決の課題として「色・フォント・余白・構図」の制御が名指しされている。SLIDE.md はこの4要素を「完全にコントロールしながら、自分好みの統一感あるプレゼン資料を短時間で生成できる」ことを目的に作られたデザインシステムだと定義されている。

含意として、AI 生成ワークフローの成熟は「作れるか」から「同じ基準で作り続けられるか」へ評価軸が移っている。生成ツールの出力品質が一定水準を超えると、次のボトルネックは個々の出来栄えではなく、複数生成物を貫く統一基準の不在になる、という構造がこのガイドの前提にある。

## 4ステップの手順構造

ガイドはスライド生成までを4ステップに分解する。著者は「初回だけStep 1が必要ですが、2回目以降はStep 3から始められます」とし、繰り返し利用時のコストを明示している（Step 2 はサンプル利用のみなら不要）。

- **Step 1：インストール** — 事前に必要なものは「Claude Code（有料プラン or APIアクセス）」と「Claude Designへのアクセス（Claudeの有料プランに含まれる）」の2点。インストールは作業フォルダで Claude Code に話しかけるだけで、3つのスキル（slide-md-creator・slide-pattern-creator・slide-deck-builder）、4種類のサンプルデザインシステム（SLIDE.md）、99種類のスライドパターン（SLIDE-PATTERN）が自動でセットアップされる。失敗時は GitHub から ZIP をダウンロードし、`skills/` の3フォルダを `~/.claude/skills/` に、`docs/SLIDE-md/` と `docs/SLIDE-PATTERN/` を作業フォルダにコピーする手動経路も用意されている。
- **Step 2：デザインシステムを用意する** — サンプルをそのまま使う場合は不要。各サンプルフォルダの `sample.html` をブラウザで開いて適合を確認する。オリジナルを作る場合は `slide-md-creator` スキルに既存スライド画像・PowerPoint・参考サイト URL を添付すると、デザイン要素の読み取り→不明点だけ3〜5問の確認→SLIDE.md と sample.html の生成、という対話が走る。著者は「sample.htmlはClaude Codeが生成する確認用の簡易サンプルです。実際にClaude Designでスライドを生成するとより高品質な仕上がりになります」と注記する。
- **Step 3：SLIDE-DECK.mdを生成する** — 著者が「ここが一番重要なステップ」と明言する工程。`slide-deck-builder` スキルが、①ブリーフのヒアリング（4問）②プレゼン内容の受け取り（テキスト貼付または .md / .pdf 添付）③SLIDE.md の選択④スライド構成案の確認（「5枚目と6枚目の順番を入れ替えて」等の指示が可能）⑤各スライドへのパターン割り当て確認（「Slide 4 → image-left-text-right に変えて」等）⑥SLIDE-DECK.md の生成、という6段階で進む。生成物 `SLIDE-DECK-{name}.md` には、デザインシステム・選択したパターン・各スライドのコンテンツひな型が1ファイルに集約される。
- **Step 4：Claude Designでスライドを生成する** — claude.ai/design を開き Slides を選択、Step 3 の SLIDE-DECK.md をアップロードして送信すると、Claude Design がデザインシステムとパターン定義を読み取りスライドを自動生成する。
## 設計上の含意：制御を生成前に外部化する

手順の構造から読み取れる設計判断は、デザインの一貫性を生成時の対話に委ねず、生成前の設計書に固定する、という点にある。Step 3 が「一番重要」とされ、コンテンツ・デザインシステム・パターン割り当てを1ファイル（SLIDE-DECK.md）に集約してから Step 4 の生成に渡す構造は、生成の非決定性を上流の明示的な仕様で抑える発想である。

評価軸についての記述も具体的だ。生成後の微調整について著者は、ツールバーの「Mark up」「Edit」に触れつつ「現時点ではこれらの操作感はあまり良くないため、軽微な修正にとどめておくのが現実的です」と限界を率直に書き、別途解決ツールを開発中だと付記する。ダウンロード形式についても、PDF は「発表・共有用途ならこれが一番確実」「デザイン通りに出力されます」、HTML はオフライン動作可、PowerPoint は「現時点ではデザインが崩れる場合があるため、微妙」と差をつけ、「迷ったらPDFを選んでおけば間違いありません」と結論づける。

含意として、このワークフローの一貫性は単一ツールの性能ではなく、設計書という中間成果物への投資で担保されている。FAQ では NotebookLM や ChatGPT でも SLIDE-DECK.md を渡せること、ただし「Claude Designが最もビジュアルデザインに特化していて高品質」とされること、99種類以外のパターンは `slide-pattern-creator` で自分のスライド画像から抽出・追加できることが補足され、設計書がツール非依存の資産として機能する構図が示されている。慣れた後は「slide-deck-builderに話しかけて → Claude Designに渡す」の2ステップに縮約される、というのが著者のまとめである。
