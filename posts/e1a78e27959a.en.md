## Executive Summary

In an August 27, 2026 engineering blog post, Uber disclosed that weekly active users of its agentic AI tooling grew 7x and weekly agent requests grew 9.4x company-wide between February and mid-August 2026, while cost per 1,000 requests fell roughly 34% and cost per session fell 52% from its June peak, both measured with the model held fixed. Uber attributes this to a six-term cost equation, benchmark-driven model selection, a "code-mode" pattern that batches tool calls into scripts, a 24-million-node context graph, and a dashboard that flags 16 distinct cost anti-patterns — together marking a shift from optimizing individual interactive sessions to running a portfolio of managed agents.

## The baseline: 70% of PRs are agent-attributed, and spend hasn't kept pace with usage

Uber Distinguished Engineer Uday Kiran Medisetty disclosed the following in the August 27, 2026 post:

- More than 70% of pull requests across the company are now attributed to local or cloud agents.
- Engineers have built over 3,600 agent skills spanning the software development life cycle, executed more than 30,000 times per day in total.
- Between February and mid-August 2026, weekly active users across all agentic offerings — deduplicated across tools — grew 7x, and weekly agentic requests grew 9.4x. Meanwhile, total AI spend has "relatively stabilized" since April.
- Holding a single model fixed (since behavior shifts with every model upgrade), cost per 1,000 model requests fell nearly 34% from its peak between February and July, and cost per session fell 52% from its June peak.
## The cost equation: six multiplied terms and outcome metrics per managed agent

Uber organizes agent usage into four layers, from most specialized to most general, with higher layers giving more control over cost, quality, and model selection. It decomposes per-session cost into six multiplied terms: the first two (adoption and engagement) are terms the company wants to keep growing, while the middle three — the work an agent does on its own behalf, on top of what an engineer actually asked for — are the optimization target.

The metrics tracked weekly and monthly span: portfolio-level totals (overall attributed cost, distinct users, per-tool cost and spend share); per-tool unit economics (cost per user, requests per user, cost per 1,000 requests, tokens per request, cost per 1 million tokens, cost per 1,000 sessions, cost per active session hour, prompt-cache hit rate); per-model economics; a "driver decomposition" that sequentially attributes cost changes to adoption, engagement, input workload, and output workload; and, for each managed agent, outcome-denominated cost (cost per merged PR, per review, per triaged alert), quality signals (revert rate, F1, mean time to resolution), and volume (diffs landed, reviews posted, alerts triaged).

## Model selection and token optimization: benchmark-driven routing and near-100% savings from code-mode

Model selection follows the same four-step process for every managed agent: build a benchmark from real work, run it on a harness that serves any model behind one interface, move to whatever is Pareto-optimal, and keep moving as the frontier shifts. The post cites uReview, Uber's AI code-review agent for all pull requests, as an example: its benchmark is built from real PRs with known bugs graded easy/medium/hard, scored on precision, recall, and F1 against those bugs plus cost per review, latency, timeouts, and noise. Switching models on this benchmark improved F1 while dramatically cutting cost per PR.

On the token side, Uber auto-compacts context at 400K tokens even for 1M-context models, defaults reasoning effort to Medium (since output and reasoning tokens bill at multiples of the input-token rate), and leans on prompt caching — cached reads cost 0.1x the standard input rate, but write premiums differ: 1.25x for a 5-minute TTL versus 2x for a 1-hour TTL. Because engineers frequently leave interactive sessions idle for more than five minutes, Uber moved those sessions from the default 5-minute TTL to a 1-hour TTL to stop forcing full-price cache rebuilds; short-lived subagent sessions keep the 5-minute TTL.

On tool calls, Uber routes over 1,000 MCP servers through one gateway, but found that loading every tool's schema into every session — over 100 tools in some configurations — added roughly 50,000–70,000 tokens of schema overhead to the initial prompt alone. It addressed this with CLI-based tool resolution and tool search, then measured the effect of "code-mode" — batching multiple tool calls into one script executed in a subprocess, with only the summary returned to the model — by running five identical SQL queries both ways in the same session: a plain `SELECT 1` went from 903 to 402 tokens (55% savings), a `GROUP BY LIMIT 20` returning 20 rows went from 1,600 to 457 tokens (71%), and a wide-table `SELECT *` returning 50 rows went from 1,431,594 to 900 tokens (nearly 100%). Bulk workflows compound these savings past 90%.

## Context graph and observability: an agent that doesn't get lost, and 16 detectable anti-patterns

Across a codebase with hundreds of millions of lines and thousands of tables, Uber found that agents spend most of their turns locating information rather than generating code. It built an "AI Context Graph" — 24 million nodes and 80 million edges across 86 node types and 117 edge types, integrating data from more than 30 internal systems including services, teams, incident logs, pull requests, design docs, deployments, datasets, and table-usage history — queryable by any agent in natural language. In a head-to-head comparison on an identical prompt, the grounded agent identified a specific table used by over 50 analysts and answered in 38 seconds; the ungrounded agent spent 20 minutes inspecting service code, spawned two subagents, hit three errors, and incorrectly concluded the dataset was unqueryable.

On the visibility side, Uber built a live cost counter into the harness status line, Slack nudges at 50/80/100% of expected spend, tiered manager-approval flows for spend upgrades, and a zero-setup session analysis dashboard that inspects session traces across all harnesses a user touches. Rather than a single aggregate score, it flags 16 distinct anti-patterns with financial impact and a targeted fix — among them running simple multi-turn sessions on a model more capable (and expensive) than the task needs, large MCP payloads persisting in context and getting re-billed on every subsequent turn, cache rebuilds forced by resuming sessions after long idle gaps, and pre-loading roughly 100,000 tokens of system instructions and tool definitions before a user has typed anything.

## What's next, and the strategic shift underneath it

Uber names its current priorities as growing the fleet of managed agents (each with target outcome metrics, an evaluation benchmark, and a Pareto-optimal model), expanding dynamic model routing across more languages and repositories, deepening context-graph integration across more autonomous agents, evolving session analytics from periodic batch detection into continuous, real-time guidance, and automating skill improvement by mining papercuts from agent execution traces. The post concludes that curbing rising AI coding spend is "a tractable engineering challenge": by eliminating wasted, zero-value token consumption rather than relying only on cheaper unit prices or downgraded tooling, Uber says it scaled agentic usage 7x while reducing unit costs across every metric it tracks and maintaining or improving output quality. The strategic shift it describes is moving from optimizing individual engineers' interactive sessions to operating a portfolio of specialized managed agents, each paired with its own evaluation benchmark and Pareto-efficient model.
