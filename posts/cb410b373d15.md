# Codex「Locked computer use」の動作条件と安全制約

## Executive Summary

Codex app の「Locked computer use」は、Mac がロックされた後でも、有効化済みであれば Codex が Computer Use を継続できる仕組みである。ただし、これは汎用的なリモートアンロック機能ではなく、「active, trusted computer use turn」に限定された短時間の自動アンロックに絞られている。

この機能は Apple authorization plug-in を macOS のアンロックフローに組み込む一方、ローカル利用の遮断、全ディスプレイの遮蔽、ローカル入力検知時の再ロックなど、限定的な運用前提で設計されている。

## Computer Use の前提条件と対象範囲

Codex app の Computer Use は、macOS 上のグラフィカルユーザーインターフェースを Codex が「see and operate」できる機能として説明されている。出典は、コマンドラインや構造化統合では不十分な場面で使う位置づけを明示している。

- エビデンス
- Computer Use は「currently available on macOS」。
- ただし提供開始時点では「except in the European Economic Area, the United Kingdom, and Switzerland at launch」。
- 利用には Computer Use plugin のインストールが必要。
- macOS から求められた場合、「Screen Recording」と「Accessibility」権限を付与する必要がある。
- 権限の役割は明示されており、Screen Recording は「so Codex can see the target app」、Accessibility は「so Codex can click, type, and navigate」。
- 含意
- 機能の成立条件は単なるアプリ内設定ではなく、macOS の OS 権限付与を含む。
- Codex は GUI を視覚的に扱う前提であり、対象アプリの状態把握と操作の両方が Screen Recording / Accessibility に依存する。
- 提供地域と OS が限定されているため、Computer Use を前提にした運用は環境依存性を持つ。
## どのタスクで Computer Use を選ぶべきか

出典は、Computer Use を GUI 依存の作業に限定して使うべきだと整理している。特に、ファイルやコマンド出力だけでは検証しにくい作業が適合例として挙げられている。

- エビデンス
- 適した用途として以下が列挙されている。
- 「Testing a macOS app, an iOS simulator flow, or another desktop app that Codex is building」
- 「Performing a task that requires your web browser」
- 「Reproducing a bug that only appears in a graphical interface」
- 「Changing app settings that require clicking through a UI」
- 「Inspecting information in an app or data source that isn’t available through a plugin」
- 「Running a scoped task in the background while you keep working elsewhere」
- 「Executing a workflow that spans more than one app」
- ローカルで構築中の Web アプリについては「use the in-app browser first」。
- 対象アプリに専用 plugin や MCP server がある場合は、「prefer that structured integration for data access and repeatable operations」。
- Computer Use の開始方法として「Mention @Computer or @AppName in your prompt, or ask Codex to use computer use」。
- 例として「Open @Chrome and verify the checkout page still works after the latest changes.」が記載されている。
- 含意
- Computer Use は第一選択ではなく、構造化された plugin / MCP server や in-app browser で代替できない場合の手段として位置づけられている。
- 向いているのは、視覚的確認・複数アプリ横断・ブラウザ操作・GUI 固有バグ再現のような、CLI では再現性や観測性が不足する作業である。
- プロンプト上で対象アプリやフローを明示する設計になっており、スコープを狭く保つことが前提になっている。
## 承認モデル: macOS 権限と Codex 側の app approvals は別管理

出典は、OS 権限と Codex 内の承認を分離している。見える・操作できることと、どのアプリを使ってよいかは別レイヤーで管理される。

- エビデンス
- 「The macOS system permissions for computer use are separate from app approvals in Codex.」
- macOS permissions は「let Codex see and operate apps」。
- App approvals は「determine which apps you allow Codex to use」。
- 「File reads, file edits, and shell commands still follow the sandbox and approval settings for the thread.」
- Codex はタスク中、「asks for your permission before it can use an app on your computer」。
- 利用者は「Always allow」を選択でき、将来の同アプリ利用では再承認不要にできる。
- 「Always allow list」は Codex settings の Computer Use セクションから削除可能。
- さらに「Codex may also ask for permission before taking sensitive or disruptive actions」。
- もし制御できない場合は「System Settings > Privacy & Security」で Codex app の「Screen Recording and Accessibility」を確認するよう案内されている。
- 含意
- Screen Recording / Accessibility を付与しただけでは、Codex が任意のアプリを自由に扱えるわけではない。
- 承認はアプリ単位で積み上がる設計であり、「Always allow」は将来タスクの自動化度を上げる一方、誤用時の影響範囲も広げる。
- ファイル編集や shell 実行は依然として sandbox と thread 単位の承認に従うため、GUI 操作だけが特権化される構造ではない。
## Locked computer use の仕組みと制約

Locked computer use は、Mac のロック後も接続済みデバイスから Computer Use を継続するための機能として定義されている。出典は、そのアンロック経路を厳しく限定し、汎用的なロック解除手段ではないことを明記している。

- エビデンス
- 「Locked computer use lets Codex use Computer Use after your Mac locks, but only after you enable it.」
- 用途は「when a Codex task needs to use desktop apps from a connected device after the Mac locks」。
- 有効化すると、Codex は「an Apple authorization plug-in that participates in the macOS unlock flow」をインストールする。
- 明示的に「It’s not a general-purpose remote-unlock path for your Mac, and it doesn’t let other apps or local processes unlock the computer.」
- 利用手順は以下。
- 「Open Codex settings > Computer Use」
- 「Enable locked computer use」
- 「Start a task that uses computer use from a connected device after your Mac’s screen has locked」
- ロック後に Codex task が Computer Use 経由でアプリへアクセスする際、Codex は「temporarily unlocks the Mac while blocking local use and preserving the locked screen protections」。
- アンロック前に、「whether the unlock attempt is for an active, trusted computer use turn」を確認する。
- その短時間の条件外では「Codex denies the unlock and asks you to unlock manually if needed」。
- 含意
- Locked computer use は「Mac がロックされた後もタスク継続可能にする」ための限定機能であり、遠隔管理や無制限のリモート復帰を目的としていない。
- unlock の可否判定は「active, trusted computer use turn」に結びつけられており、常時利用可能なバックドア型機能とは異なる。
- 「connected device」からの継続利用を前提にしており、Codex の実行文脈が継続していることが条件になる。
## Locked use の安全策と運用上の禁止事項

出典は、Locked use の safeguards と、Computer Use 全体に対する安全ガイダンス、さらに機能が扱えない対象を具体的に列挙している。

- エビデンス
- Locked use の safeguards:
- 「The authorization window is short-lived and scoped to the current unlock attempt.」
- 「Automatic unlock is available only to Codex during active computer use turns.」
- 「Codex covers every display while the desktop is temporarily unlocked.」
- 「If Codex detects local keyboard or pointer input, it relocks the Mac and pauses automatic unlock until you unlock it manually.」
- Computer Use 全体について、Codex は「view screen content, take screenshots, and interact with windows, menus, keyboard input, and clipboard state in the target app」。
- また「visible app content, browser pages, screenshots, and files opened in the target app」を、タスク実行中に Codex が処理しうる context として扱うよう求めている。
- 安全ガイダンスとして以下が示されている。
- 「Give Codex one clear target app or flow at a time」
- 「You can stop the task or take over your computer at any time」
- 「Keep sensitive apps closed unless they’re required for the task」
- 「Avoid tasks that require secrets unless you’re present and can approve each step」
- 「Review app permission prompts before allowing Codex to use an app」
- 「Use Always allow only for apps you trust Codex to use automatically in future tasks」
- 「Stay present for account, security, privacy, network, payment, or credential-related settings」
- 「Cancel the task if Codex starts interacting with the wrong window」
- ブラウザ利用時は、「it can interact with pages where you’re already signed in」。
- Web サイトは「malicious or misleading content」を含みうると警告されている。
- 並行利用したい場合は「ask Codex to use a different browser」。
- 機能制限として、「can’t automate terminal apps or Codex itself」。
- 理由は「since automating them could bypass Codex security policies」。
- さらに「can’t authenticate as an administrator or approve security and privacy permission prompts on your computer」。
- GUI 経由の変更については、「may not appear in the review pane until they’re saved to disk and tracked by the project」。
- データ処理については「Your ChatGPT data controls apply to content processed through Codex, including screenshots taken by computer use」。
- 含意
- Locked use の保護策は、アンロック状態そのものを秘匿・短時間化し、ローカル同時利用を排除する方向に揃っている。
- ブラウザ、クリップボード、画面内容、スクリーンショットが処理対象に入るため、秘匿情報やログイン済みセッションがある環境では作業範囲を狭く保つ必要がある。
- terminal apps と Codex 自身を自動化対象から除外している点は、Computer Use が Codex の既存 security policies を迂回しないようにする設計制約と読める。
- 管理者認証や security/privacy permission prompts の承認を代行できないため、OS の高権限操作は人手関与が残る。
