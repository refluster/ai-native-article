# Claude Managed Agentsの更新整理：dreaming、outcomes、multiagent orchestration、webhooksの要点

## Executive Summary

Anthropicは2026年5月6日、Claude PlatformのManaged Agentsに対して、**dreaming**をresearch previewとして導入し、あわせて**outcomes**、**multiagent orchestration**、**webhooks**を開発者向けに提供開始した。発表の中心は、エージェントがセッションをまたいで学習を整理し、評価基準に沿って自己修正し、必要に応じて複数の専門エージェントへ作業を分担できるようにする点にある。

この更新により、Managed Agentsは「単発の応答生成」ではなく、「長期・複雑・並列な業務を少ない人手で回す」ための実行基盤として位置づけられている。本文では、自己改善のための記憶設計、評価ループ、並列分業、実運用事例が一体で示されている。

## dreaming：過去セッションを見直して記憶を再編する仕組み

dreamingは、エージェントの過去セッションとmemory storesを見直し、パターン抽出と記憶のキュレーションを行う「scheduled process」として説明されている。Managed Agentsにおけるmemoryの補完機能として設計されており、セッション間での自己改善を狙う。

- **エビデンス**
- Anthropicは「Today we're launching dreaming in Claude Managed Agents as a research preview.」と述べている。
- dreamingは「reviews your agent sessions and memory stores, extracts patterns, and curates memories so your agents improve over time」と定義されている。
- 利用者の制御について、「dreaming can update memory automatically, or you can review changes before they land」とされる。
- dreamingが見つける対象として、「recurring mistakes」「workflows that agents converge on」「preferences shared across a team」が挙げられている。
- さらに「It also restructures memory so it stays high-signal as it evolves」と記載されている。
- memoryとの関係は、「Memory lets each agent capture what it learns as it works」「Dreaming refines that memory between sessions」と整理されている。
- 提供状況は「Dreaming is available in Managed Agents on the Claude Platform; developers can request access here」および末尾で「Dreaming is available in research preview」と明記されている。
- **結論**
- dreamingは、単に履歴を保存する機能ではなく、**保存された記憶を後処理して再編する層**として位置づけられている。
- 特に本文が「long-running work and multiagent orchestration」に有効だと述べることから、長期案件や複数エージェント運用では、逐次的なメモリ蓄積だけでは足りず、**事後的な要約・抽出・整理**が前提になっている。
- 「a single agent can’t see on its own」とあるため、dreamingの役割は個別エージェントの文脈窓を超えて、**横断的な運用知見を取り出すこと**にある。
## outcomes：graderを分離して自己修正を回す評価ループ

outcomesは、開発者が成功条件をrubricとして定義し、その基準に対して別個のgraderが出力を評価する仕組みである。graderはエージェント本体とは別のcontext windowで動作し、評価と生成を分離している。

- **エビデンス**
- Anthropicは「With outcomes, you write a rubric describing what success looks like and the agent works toward it」と説明している。
- 評価方式について、「A separate grader evaluates the output against your criteria in its own context window, so it isn't influenced by the agent's reasoning」と明記している。
- 不十分な場合の挙動は、「When something isn't right, the grader pinpoints what needs to change and the agent takes another pass」とされる。
- 適用対象として、「a structural framework, a presentation standard, or a set of requirements that need to be met」が例示されている。
- 主観的品質にも使え、「whether copy matches a brand voice or a design follows visual guidelines」とされる。
- 性能面では、「In testing, outcomes improved task success by up to 10 points over a standard prompting loop, with the largest gains on the hardest problems」とある。
- ファイル生成では「+8.4% task success on docx and +10.1% on pptx in our internal benchmarks」と記載されている。
- 運用面では「You can also now define an outcome, let the agent run, and get notified by a webhook when it's done」とされる。
- 末尾で「outcomes, multiagent orchestration, and memory are available in public beta as part of Managed Agents」と提供段階が示されている。
- **結論**
- outcomesの中核は、**生成者と評価者を分離した自己修正ループ**にある。本文がわざわざ「isn't influenced by the agent's reasoning」と書くのは、生成時の思考過程をそのまま自己採点に流し込まないためである。
- 適用対象が要件充足だけでなくブランドボイスやデザインガイドラインにも広がっているため、outcomesは**形式的正しさの検査だけでなく、基準化可能な主観品質の運用**にも向いている。
- webhookの追加により、outcome定義後は人が逐次監視せず、**完了通知ベースの非同期ワークフロー**へ組み込みやすくなっている。
## multiagent orchestration：リードエージェントが専門エージェントへ並列委譲する

multiagent orchestrationは、1つのエージェントで処理しきれない作業を、リードエージェントが分割し、モデル・プロンプト・ツールの異なる専門エージェントへ委譲する仕組みとして提示されている。

- **エビデンス**
- Anthropicは「When there is too much work for a single agent to do well, multiagent orchestration lets a lead agent break the job into pieces and delegate each one to a specialist with its own model, prompt, and tools」と説明している。
- 例として、「a lead agent can run an investigation while subagents fan out through deploy history, error logs, metrics, and support tickets」と書かれている。
- 実行形態は「These specialists work in parallel on a shared filesystem and contribute to the lead agent's overall context」とされる。
- 継続的なやりとりについて、「The lead agent can check back in with other agents mid-workflow because events are persistent and every agent remembers what it's done」と記載されている。
- 可視化について、「You can also trace every step in the Claude Console: which agent did what, in what order, and why」と説明されている。
- 提供段階は末尾で「multiagent orchestration ... are available in public beta」と示されている。
- **結論**
- multiagent orchestrationは、単なる並列化ではなく、**役割分化された実行体制の管理**として設計されている。本文が「its own model, prompt, and tools」と書くため、専門化の単位はタスクだけでなく、モデル選択や道具立ても含む。
- shared filesystemとpersistent eventsの組み合わせにより、これは独立した子タスクの一回限りの投げ分けではなく、**途中で再参照・再指示できる協調的な分業**である。
- Claude Consoleで「which agent did what, in what order, and why」を追跡できる点から、Anthropicは自律性だけでなく、**委譲の監査可能性**を前提要件として扱っている。
## 導入事例に見る運用パターン：法務、ビルド分析、執筆、文書品質確認

記事は、dreaming・outcomes・multiagent orchestrationを実務でどう組み合わせているかを、4社の事例で示している。各事例は、長期記憶、並列分析、品質評価、速度改善という異なる導入目的に対応している。

- **エビデンス**
- **Harvey**
- 「Harvey uses Managed Agents to coordinate complex legal work like long-form drafting and document creation」
- 「With dreaming, their agents remember what they learned between sessions, including filetype workarounds and tool-specific patterns」
- 「Completion rates went up ~6x in their tests」
- **Netflix**
- 「Netflix's platform team built an analysis agent that processes logs from hundreds of builds across different sources」
- 「With changes that affect thousands of applications, what matters is finding the issues that recur across many of them」
- 「Multiagent orchestration lets the agent analyze batches in parallel and surface only the patterns worth acting on」
- **Spiral by Every**
- 「Spiral by Every is using multiagent orchestration and outcomes to power the writing agent behind their new API and CLI」
- 「The lead agent runs on Haiku」
- 「then delegates the drafting to subagents running on Opus」
- 「When a user asks for multiple drafts, the subagents run in parallel」
- 「Each draft is scored against a rubric of Every's editorial principles and the user's voice, both pulled from memory」
- 「Only drafts that clear the bar are returned」
- **Wisedocs**
- 「Wisedocs built a document quality check agent on Managed Agents, using outcomes to grade each review against their internal guidelines」
- 「Reviews now run 50% faster, while staying aligned with their team's standards」
- **結論**
- Harveyの記述からは、dreamingが**ファイル形式ごとの回避策**や**ツール固有の運用知識**を蓄積対象にしていることが読み取れる。これは抽象的な知識管理ではなく、実作業の摩擦を減らすための記憶である。
- Netflixの事例では、multiagent orchestrationの価値は単なる処理速度ではなく、複数ソース・多数ビルドから**再発パターンだけを抽出する集約能力**に置かれている。
- Spiral by Everyの構成は、**リードはHaiku、ドラフトはOpus**というモデル分担を明示しており、multiagent orchestrationがモデル階層を含む設計であることを示している。
- Wisedocsの事例は、outcomesがレビューの品質担保と処理時間短縮を両立させる形で使われていることを示す。記事の表現に従えば、評価基準の明文化が**速度向上と標準準拠の両立**に結びついている。
## 提供形態と導入導線：research preview / public betaの切り分け

今回の発表では、各機能の提供段階が明示され、dreamingのみがresearch preview、その他の主要機能はpublic betaとして整理されている。導入導線はClaude Platform、documentation、Claude Consoleの3点に集約されている。

- **エビデンス**
- 記事のメタ情報では、カテゴリは「Product announcements」、プロダクトは「Claude Platform」、日付は「May 6, 2026」。
- 本文末尾で「Dreaming is available in research preview, outcomes, multiagent orchestration, and memory are available in public beta as part of Managed Agents」と書かれている。
- 導入案内として「To get started with dreaming, request access here」
- さらに「Explore our documentation to learn more or visit the Claude Console to deploy your first agent」と記載されている。
- **結論**
- Anthropicは今回の更新を、Managed Agents全体の一般提供ではなく、**機能ごとに成熟度を分けて公開する方式**で展開している。
- dreamingは申請制のresearch previewであり、outcomes・multiagent orchestration・memoryはpublic betaであるため、実装上の安定度やアクセス条件は機能ごとに異なる。
- Claude Consoleが「deploy your first agent」の導線として示されていることから、Managed Agentsは記事上、概念紹介にとどまらず、**即時デプロイ可能なプラットフォーム機能**として扱われている。
