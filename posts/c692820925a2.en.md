## Executive Summary

On 21 October 2026 (GTC Berlin), NVIDIA announced the OpenShell Reference Architecture for building, containing, observing and enforcing AI agents on enterprise infrastructure and at the edge. The central design choice is to split agent safety across an execution layer (OpenShell on Vera CPUs) and a monitoring-and-enforcement layer running outside it (NVIDIA Sentry on BlueField-4 DPUs), instead of leaving it to software policy alone. NVIDIA says the architecture is available now.

## What was announced

The announcement bundles four components into one reference build.

- **NVIDIA Vera Rubin** handles model inference. Vera Rubin NVL72 can be shifted between pretraining, post-training and inference, and NVIDIA says it delivers 30x higher throughput per megawatt for agentic workloads.
- **NVIDIA Vera CPUs** run agent harnesses and tool use, and run the open source OpenShell. NVIDIA claims 2x the performance of x86 processors with greater energy efficiency.
- **NVIDIA OpenShell** is open source software that gives autonomous agents a secure runtime boundary.
- **NVIDIA BlueField-4 DPUs with NVIDIA Sentry**, built on DOCA, form a unified security framework that monitors agent behavior out of band and enforces policy in silicon.
At the edge, the release names NVIDIA RTX Spark, DGX Spark and DGX Station. Supported operating systems include Linux and Kubernetes from Canonical, SUSE and Red Hat, and Windows using Microsoft Execution Containers (MXC). It is also said to run on cloud operating systems from AWS, Google Cloud and Microsoft Azure.

## The design point: put the enforcer outside the software boundary

The most concrete claim in the release is this: BlueField and NVIDIA Sentry provide "in-silicon security enforcement". If an agent tries to move outside its software boundary, Sentry quarantines and stops it "in milliseconds". NVIDIA also says Sentry boosts agent capacity by up to 20%.

Jensen Huang put it this way: "agents can think on Rubin, act on Vera and be governed on BlueField."

Read structurally, the compute that runs the agent and the authority that can stop it sit on different physical parts. The stop mechanism is not placed inside the same trust boundary as the agent's own process.

## Partners and the state of implementation

The release names a wide set of participants.

- **Model builders**: agents from Anthropic, Cohere, Google, Meta, OpenAI, Perplexity, Reflection and SpaceX Super Intelligence can run on OpenShell infrastructure.
- **Security vendors**: 1Password, Check Point, CrowdStrike, Cisco, F5, Fortinet, Microsoft, Okta, Palo Alto Networks, TrendAI and Zscaler are integrating support into their agent security products.
- **Banks**: Europe's BBVA and Santander are exploring it as a framework for agent safety, security and governance.
- **Enterprise software**: SAP is integrating it with the Joule Studio runtime. ServiceNow announced general availability of ServiceNow Arc, a personal long-running agent whose actions are governed at runtime by its Super Intelligence Control Tower and enforced by OpenShell. ServiceNow's AI Passport carries policies to OpenShell and Sentry so that enterprises can revoke an agent's access across software and hardware within seconds.
- **Systems and cloud**: Dell Technologies, Cisco, HPE, Lenovo and Supermicro are building infrastructure, and providers including CoreWeave, Crusoe, Nebius, Oracle Cloud Infrastructure and Vultr are deploying OpenShell-ready capacity.
## Separating fact from interpretation

Every figure and claim above comes from NVIDIA's own press release. The 30x, 2x, 20% and millisecond-quarantine claims come with no third-party measurement. The release's closing disclaimer also says many features will be offered on a when-and-if-available basis and are not a commitment.

Three implications follow from what the release says.

- **The location of safety has moved.** Agent safety shifts from prompts and permission settings to a component of the compute platform.
- **Revocation speed is now a stated spec.** ServiceNow describes revoking agent access in "seconds". Operators will be asked whether their own revocation procedures can keep up.
- **A lock-in question remains.** The reference build assumes NVIDIA CPUs, DPUs and GPUs. The release does not say whether equivalent enforcement exists on other vendors' hardware.
