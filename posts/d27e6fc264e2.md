## Executive Summary

Anthropic Institute の Marina Favaro と Jack Clark は記事「When AI builds itself」で、AI が AI 開発そのものを加速させている直接証拠を公開した。2026年第2四半期、同社エンジニア1人あたりのコード生産量は2024年の8倍に達し、本番にマージされるコードの80%超を Claude が書いている。著者らは「再帰的自己改善（recursive self-improvement）」——AI が自らの後継機を完全に自律設計する状態——にはまだ到達しておらず不可避でもないとしつつ、多くの組織の備えより早く訪れうると警告する。

## 「再帰的自己改善」とは何か——まだ到達していないという前提

記事の定義では、再帰的自己改善とは「十分な計算資源を与えられれば、AI システムが自らの後継機を完全に自律的に設計・開発できる」状態を指す。著者らは「We are not there yet, and recursive self-improvement is not inevitable（まだ到達しておらず、不可避でもない）」と明記する一方、「But it could come sooner than most institutions are prepared for（だが多くの組織が備えるより早く来うる）」とも述べる。

記事は開発の段階を図で示す。2021–2023年「最初の Claude を構築（人がノートPCでコードを書く）」、2023–2025年「チャットボット（短いコード片を生成しコピー＆ペースト）」、2025–2026年「コーディングエージェント（自らコードを書き編集）」、Today「自律エージェント（自らコードを実行し、他のエージェントに数時間の作業を委譲）」、そして「20XX?——Closing the loop（エージェントが自らモデルを構築・訓練しうる）」。

## 外部ベンチマーク:加速する能力曲線

**証拠（事実）**

- METR の計測では、AI が自律的に確実に完了できるタスクの「時間地平」は約4か月ごとに倍増しており、以前の約7か月ごとから加速している。2024年3月の Claude Opus 3 は人間で約4分のタスク、1年後の Claude Sonnet 3.7 は約1.5時間、さらに1年後の Claude Opus 4.6 は12時間のタスクをこなした。
- SWE-bench（実在の OSS コードベースと実際のバグ報告を渡し、テストを通す修正を求めるテスト）で、スコアは2年間で「low single digits（数%）」から飽和（saturation）へ移行した。
- CORE-Bench（公開論文の結果を再現できるかのテスト）は2024年の約20%から15か月後に飽和。METR は Claude Mythos Preview が「at least 16 hours」稼働でき「新しいタスクなしに計測できる上端」にあると報告した。
**結論（含意）** 公開ベンチマークは能力水準を示すが、AI 開発自体の加速は測れない。だからこそ著者らは社内データへ踏み込む——ここが本記事の核心である。

## Anthropic 内部データ:エンジニアリングの自動化

**証拠（事実）**

- 2026年5月時点で、Anthropic のコードベースにマージされるコードの80%超を Claude が書いた。Claude Code が2025年2月にリサーチプレビューで公開される前は「low single digits」だった。
- エンジニア1人あたり1日のマージ行数は2021–2024年は横ばいだったが、Claude が「提案」から「実行」へ移った2025年に上昇を始め、長時間の自律稼働が始まった2026年に傾きが再び急になった。2026年第2四半期の典型的なエンジニアは2024年の8倍のコードを1日にマージした。
- 2026年4月、Claude は800件超の修正を投入し、ある種の API エラーを1000分の1に削減。監督したエンジニアは、人間なら4年かかる作業だと見積もった。
- 2026年3月、研究チーム横断130名への調査で、回答者の中央値は Mythos Preview により約4倍の生産量と推定した（著者らは実際の上昇幅はやや低いと注記）。
**結論（含意）** 著者らは「行数は質ではなく量を測る」ため8倍は真の生産性向上の過大評価だろうと自ら認める。質の改善の証左として、自動 Claude レビューワが過去の claude.ai インシデントの原因バグの約3分の1を本番到達前に捕捉できたはずという遡及分析を挙げる。Claude が書くコードは「2025年後半は人間より劣り、現在は同等、年内には上回る」と見る。

## 研究プロセス:実験実行から「次の一手」の判断へ

**証拠（事実）**

- 目標と成功指標を固定した上でコードを高速化させるテストでは、2025年5月の Claude Opus 4 が約3倍、2026年4月の Claude Mythos Preview が約52倍の高速化を達成した（熟練人間は4倍到達に4〜8時間）。
- 2026年4月、弱いモデルが強いモデルを確実に監督できるか（weak-to-strong）という未解決問題で、Claude エージェント群は性能差の97%を累計800時間・約$18,000の計算資源で回復した。人間研究者2名は約1週間で約23%だった。ただし本番規模モデルへの転移は不完全で、問題の選定と採点基準は人間が用意した。
- 研究セッションの「次の一手」を人間の選択と比較する評価（n=129、人間側に改善余地があった局面を選択）で、2025年11月の Opus 4.5 は51%、2026年4月の Mythos Preview は64%、人間の選択を上回った。
**結論（含意）** 著者らは、AI が今なお弱いのは「research taste and judgment（研究上の趣味・判断）」——どの問題が重要か、どの結果を信じるか、いつ袋小路だと見切るか——だと結論づける。これが「今日の AI」と「自らの後継機を自律設計しうる未来の AI」を隔てる差である。

## 三つの未来と「何をすべきか」

著者らは三つのシナリオを示す。(1) 趨勢が S字曲線で頭打ちになるが現在の能力が広く普及する、(2) 人間が方向性を決めつつ効率改善が複利的に続く（100人企業が1万〜10万人規模の仕事をこなす）、(3) AI が完全な再帰的自己改善に到達し後継機を作り始める。著者らは(2)が最も蓋然性が高いと見るが、Amdahl の法則により「人間によるコードレビュー」が新たなボトルネックになったと自認する。

政策面では、societal structures と alignment 研究が追いつくよう開発を検証可能な形で減速・一時停止できる「選択肢」を持つことが望ましいとする。ただし一方的な停止は先頭走者を入れ替えるだけだと指摘する。中距離核戦力（INF）条約のような検証体制は構築に数十年を要した一方、訓練ランはミサイルサイロより秘匿が容易で、本問題の「detectability（検出可能性）」は他技術より難しいという。なお Project Glasswing では Mythos Preview が初週で1万件超の高・重大度の脆弱性を発見し、サイバー防御のボトルネックが「発見」から「迅速なパッチ適用」へ移ったと報告されている。
