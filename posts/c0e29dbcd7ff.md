## Executive Summary

Anthropic の公式ドキュメント「Prompting Claude Fable 5」は、新モデル Claude Fable 5（および Claude Mythos 5）が Claude Opus 4.8 と比べて挙動が変わり、プロンプトやスキャフォールディングの更新を要すると明言している。最大の変化は 1 リクエストが高 effort で数分、自律実行では数時間に及ぶ長時間化であり、クライアントのタイムアウトやハーネスを同期ブロッキングから非同期チェックへ組み替える必要がある。指示追従の強化により挙動は短い指示で操舵できる一方、reasoning を応答本文に出力させる旧来の指示は `reasoning_extraction` の拒否を誘発するため、移行時に既存スキルの棚卸しが求められる。

## Opus 4.8 からの能力向上

ドキュメントは、Claude Fable 5 が「以前は複雑・長時間・曖昧すぎて扱えなかった問題」に取り組み、人が数時間から数週間かける end-to-end の作業に特に有効だと述べる。最良の成果を出しているチームは、単純なワークロードで試すのではなく「最も難しい未解決の問題」に適用しているという。Claude Opus 4.8 との比較で挙げられた向上点は次のとおり。

- **Long-horizon autonomy（長期自律）**：複数日にわたる目標指向の実行を、長く複雑なタスク全体で強い指示保持を保ちながら完遂する。
- **複雑かつ明確に仕様化された問題での first-shot correctness**：早期テスターは、従来なら数日の反復を要したシステムを単一パスで実装した例を報告した。
- **Vision**：密な技術画像・Web アプリ・詳細なスクリーンショットを、より少ない出力トークンで高精度に解釈し、反転・不鮮明・ノイズの多い画像を扱うために bash と crop ツールを使うよう訓練されている。
- **Enterprise workflows**：財務分析・スプレッドシート・スライド・文書で、指示に従いスコープ内に留まりプロ品質の出力を出す。
- **Code review and debugging**：バグ発見の recall が Opus 4.8 より明確に高く、コードベースやリポジトリ履歴の探索を含む。
- **曖昧さの処理と、subagent への委任・協調**：並列 subagent の派遣と維持が大幅に信頼できるものになった。
一方でドキュメントは、Claude Fable 5 が攻撃的サイバーセキュリティおよび生物・生命科学の作業向けではないと明記する。これらの領域のリクエストは `stop_reason: "refusal"` を返しうる。

## 実行時間と effort の再設計

移行時に各チームが最も強く直面する変化として挙げられるのが、実行の長時間化である。難タスクでは高い effort 設定の 1 リクエストが数分に及び、コンテキスト収集・構築・自己検証を要する場合はなおさら長くなる。自律実行は数時間に延びうる。

- **evidence（ドキュメントの指示）**：移行前にクライアントのタイムアウト、ストリーミング、ユーザー向け進捗表示を調整し、ブロッキングではなくスケジュールジョブなどで非同期に実行状況を確認するようハーネスを組み替えることを推奨している。
- **effort レベル**：effort は Claude Fable 5 における知能・レイテンシ・コストのトレードオフを制御する主要なつまみである。多くのタスクでは `high` を既定とし、最も能力を要するワークロードには `xhigh`、定型作業には `medium` か `low` を用いる。Claude Fable 5 では低い effort でも十分機能し、しばしば旧モデルの `xhigh` を上回る。タスクが完了するが必要以上に時間がかかる場合や、より対話的に進めたい場合は effort を下げる。
**conclusion（含意）**：同期的にレスポンスを待つ従来の統合前提は成り立たない。移行はモデル差し替えではなく、タイムアウト・進捗 UI・非同期監視を含むハーネス設計の見直しとして扱う必要がある。

## 自律実行を支える指示とスキャフォールディング

指示追従が強化されたため、挙動ごとに逐一列挙するのではなく短い指示で操舵できる。無指示だと高 effort で過剰に精緻化しがち（追求しない選択肢の調査、根本原因の長い説明、過度に構造化された PR 説明、次行を解説するコメントなど）だが、簡潔さを求める一文だけで各パターンの列挙と同等の効果が得られる。ドキュメントが挙げる主要パターンは次のとおり。

- **進捗主張の接地（Ground progress claims）**：長い自律実行では、実際のツール結果に照らして進捗を監査するよう指示する。Anthropic のテストでは、これによって捏造されたステータス報告が――それを誘発するよう設計されたタスクでも――ほぼ排除された。
- **境界の明示（State the boundaries）**：Claude Fable 5 は依頼していない行動（頼まれていないメールの下書き、防御的な git ブランチのバックアップ作成）をとることが稀にある。何をすべきで何をすべきでないかを明示的に定義する。
- **Parallel subagents**：旧モデルより積極的に並列 subagent を派遣する。委任が適切な場面を明示し、各 subagent の返却を待つブロッキングより非同期通信を優先する。コンテキストを保持する長命の subagent はキャッシュ読み取りでコストと時間を節約し、最も遅い subagent がボトルネックになるのを避ける。
- **メモリシステムの構築**：過去の実行から学びを記録し参照できると特に高い性能を示す。Markdown ファイルのような単純な場所を用意すればよい。
ごく稀な失敗モードも記載される。長いセッションの深部で、対応するツール呼び出しを伴わず「これから X を実行する」という意図表明だけでターンを終える、あるいは十分に進められるのに許可を求めて止まることがある。「continue」や「go ahead and do it end to end」で解消する。また残トークンのカウントダウンをモデルに見せると、新セッションの提案や作業の切り詰めを誘発しやすいため、コンテキスト予算の明示的なカウントは可能な限り見せないよう助言している。

## 移行時のスキャフォールディング変更と安全分類器

Claude Fable 5 は攻撃的サイバーセキュリティ技術（エクスプロイト・マルウェア・攻撃ツールの構築）、生物・生命科学コンテンツ（実験手法や分子機構）、およびモデルの要約された thinking の抽出を対象とする安全分類器を実行する。良性のサイバーセキュリティ作業や有益な生命科学タスクもこれらの保護を発動させうる。拒否されたリクエストを自動で再ルートするには、Claude Opus 4.8 へのサーバー側またはクライアント側フォールバックを設定する。

ドキュメントが推奨するスキャフォールディング変更は次のとおり。

- **難易度レンジの上端から始める**：旧モデルに割り当てるより難しいタスクを選び、スコープ設定・確認質問・実行を Claude Fable 5 に行わせる。
- **自己検証を明示する**：別個で新鮮なコンテキストを持つ検証用 subagent は、自己批判より優れる傾向がある。長時間タスクでは一定間隔で仕様に照らして subagent で検証させるよう指示する。
- **既存プロンプトとスキルのリファクタ**：旧モデル向けに作られたスキルは Claude Fable 5 には過度に規範的で、出力品質を下げうる。既定性能の方が良ければ古い指示の削除を検討する。
- **reasoning を応答に再現させない**：内部の reasoning を応答テキストとしてエコー・転記・説明させるプロンプトやスキルは `reasoning_extraction` の拒否カテゴリを誘発し、Claude Opus 4.8 へのフォールバック増加を招きうる。reasoning の可視性が必要なら adaptive thinking の構造化 `thinking` ブロックを読む。
- **send-to-user ツールの用意**：長時間の非同期エージェント向けに、ターンを終えずにユーザーへメッセージをそのまま届けるクライアント側ツールを設ける。ツール入力は要約されないため内容がそのまま届く。ただしツール定義だけでは不十分で、システムプロンプト内の誘導がないと Claude Fable 5 はほとんど呼び出さない。ナレーションや内部推論をこのツールに流すのは目的を損なう。
**conclusion（含意）**：この移行の核心は能力向上そのものより、旧モデル向けに積み上げた「規範的な指示」の棚卸しである。API パラメータ側でも adaptive thinking のみ・要約された thinking 出力のみ・extended thinking の予算指定なし・`refusal` stop reason といった変更が入っており、能力向上を機に、どの指示・ツール・ガードレールが今なお必要かを再評価することが移行作業の実体となる。
