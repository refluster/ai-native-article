# ECC: Claude Code/Codex/Cursor 向け「agent harness performance optimization system」の実装内容

## Executive Summary

ECC は、単なる設定集ではなく、「skills, instincts, memory optimization, continuous learning, security scanning, and research-first development」を一体化した「The harness-native operator system for agentic work」として設計された GitHub リポジトリである。出典上は、Claude Code だけでなく、Codex、Cursor、OpenCode、Gemini、Zed、GitHub Copilot など複数ハーネスをまたいで再利用できる運用基盤として位置づけられている。

公開面では「60 agents, 232 skills, and 75 legacy command shims」を備え、`ECC v2.0.0-rc.1` では GUI ダッシュボード、Rust 製 control-plane prototype、operator workflow 拡張、portable handoff 用の status 機能が追加された。含意として、ECC はプロンプトや単発コマンドの配布ではなく、AI コーディング環境の実行面・状態管理・継続学習・監査を束ねる「ハーネス運用層」を OSS として前面化している。

短い説明として、ECC は AI エージェントのための設定ファイル集ではなく、複数の開発ハーネス上で動く実運用システムとして提示されている。

- 対応対象として「Claude Code , Codex , Cursor , OpenCode , Gemini , Zed , GitHub Copilot , and other AI agent harnesses」を列挙している
- 「170+ contributors」「12+ language ecosystems」「182K+ stars | 28K+ forks」と公開規模を示している
- 結論

ECC は、利用者が直接触る表面として、エージェント、スキル、ルール、フック、コマンド、プラグイン・マニフェストをまとめて提供している。

## インストールと運用ポリシー: plugin path と manual path を混在させない

README では、導入手順よりも「壊れやすい導入パターンを避ける」ことに相当量の説明が割かれている。

- エビデンス
- Quick Start 冒頭で「Pick one path only」と明示している
- 「Do not stack install methods. The most common broken setup is: `/plugin install` first, then `install.sh --profile full` or `npx ecc-install --profile full` afterward.」
- 推奨経路として
- `/plugin marketplace add https://github.com/affaan-m/ECC`
- `/plugin install ecc@ecc`
を示す

- 識別子の違いとして
- 「GitHub source repo: `affaan-m/ECC`」
- 「Claude marketplace/plugin identifier: `ecc@ecc`」
- 「npm package: `ecc-universal`」
を並記し、「they are not interchangeable」としている

- plugin install 後の rules 配布制約について「Claude Code plugins cannot distribute rules automatically.」とある
- そのため `~/.claude/rules/ecc/` 以下に `rules/common` や `rules/typescript` を手動コピーする手順が示されている
- manual install は「Use this only if you are intentionally skipping the plugin path: `./install.sh --profile full`」「If you choose this path, stop there. Do not also run `/plugin install` .」とされる
- アンインストールについても `node scripts/uninstall.js --dry-run`, `node scripts/uninstall.js`, `node scripts/ecc.js doctor`, `node scripts/ecc.js repair` を案内している
- 結論
- ECC は高機能である一方、インストール経路の重複がそのまま重複挙動・重複スキル・重複フックに直結するため、導入ポリシー自体が製品仕様の一部になっている
- `plugin` と `manual` を厳密に分離しているのは、単なる UX 配慮ではなく、実行時競合を避けるための運用制御である
- rules が plugin で自動配布されない制約から、ECC はハーネス機能の限界を前提に、配布面を「plugin」「manual copy」「CLI installer」に分解している
