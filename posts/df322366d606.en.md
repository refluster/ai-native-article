## Executive Summary

The survey paper by Yiqi Wang et al., “From Agent Traces to Trust: A Survey of Evidence Tracing and Execution Provenance in LLM Agents” (arXiv:2606.04990v4), argues that the reliability of autonomous LLM agents should be understood not in terms of “whether the final answer was correct,” but in terms of the traceability of the execution process itself. The paper names the absence of this process a **process-level accountability gap** and presents a six-dimensional taxonomy for organizing agent execution. Its focus is the design of **provenance**: a framework that links verification, debugging, safety controls, and auditing by making it possible to examine which evidence supported which claim.

## Why “Did It Get the Right Answer?” Is Not Enough

The paper’s starting point is straightforward: “Final-answer accuracy evaluates only the endpoint of an execution; it does not explain how an output was produced, which evidence supported each claim.” For agents that operate across tool calls, retrieval, memory, and multi-agent communication, even a correct answer does not let us determine after the fact whether it was derived from legitimate evidence or produced by contaminated inputs.

Here the paper draws a clear distinction between two concepts.

- **Execution provenance**: A typed graph representing the entire agent execution. It is a “complete” representation that includes evidence units, execution artifacts (retrieved documents, tool calls, memory accesses, claims, actions), and the causal, dependency, and contradiction relations among them.
- **Evidence tracing**: A subproblem within provenance that projects only the “support relations” linking evidence to an agent’s claims, judgments, and actions.
**Implication**: Evidence tracing is only one part of execution provenance. Much existing work focuses on evidence tracing in settings such as citation attribution in RAG, but full provenance graphs that span tools and memory remain largely unexplored. That is the paper’s core problem setting.

## A Six-Dimensional Taxonomy: What to Record, At What Granularity, and When

The core of the paper is a six-dimensional taxonomy, summarized in Table 1, “Taxonomy of evidence tracing and execution provenance in LLM agents.” It organizes the design space as follows.

- **Trace sources**: Reasoning, retrieval, tool use, MCP boundaries, memory, environment, multi-agent communication
- **Evidence and execution units**: Documents, passages, observations, tool outputs, memory items, claims, policies, actions
- **Provenance relations**: support, derive, depend-on, contradict, invalidate, trigger, update, use, generate
- **Granularity**: From the full execution (run-level) down to token- and span-level
- **Timing**: Pre-execution, runtime, post hoc, continuous
- **Representation formats**: Structured logs, execution graphs, evidence graphs, claim-support graphs, runtime state
On representation format, Figure 3, “Running example of a provenance graph,” presents a concrete example in which typed relations such as Support / Derive / Depend-on / Contradict / Invalidate / Update connect queries, passages, claims, tools, memory, and actions. **Separating evaluation from conclusion**: the paper’s argument is that only by representing execution as this kind of typed graph—not as a flat chronological log—can we mechanically trace which evidence supported which claim and where contradictions emerged.

## Tools and Memory: Two Attack Surfaces That Provenance Can Protect

The paper shows the practical value of provenance most concretely in tool use (Section 4) and memory (Section 5).

For tool use, **indirect prompt injection** is identified as a central threat. Because external content can contaminate a tool’s context, the paper argues that information-flow tracking and taint tracking are necessary. It highlights the following representative defenses.

- **Agent-Sentry** — Per-argument data-flow tracking
- **FIDES** — Information-flow labels
- **NeuroTaint** — Taint propagation across semantic transformations
For memory, the paper treats memory as **provenance-bearing evidence** and analyzes it through four aspects: write lineage, retrieval validity, contradiction management, and verification. Table 4, “Agent memory through a provenance lens,” scores 11 systems across write / retrieval / conflict / staleness / verification. The paper’s assessment is blunt: **current memory systems such as MemGPT, A-MEM, and Mem0 prioritize recall over accountability, and remain weak on contradiction handling and contamination tracking**.

**Implication**: Both tool systems and memory systems have largely been designed around permissions and recall performance alone. The paper’s consistent argument is that only when provenance is designed alongside them—argument-level lineage for tools, attribution of write origins for memory—can attacks be distinguished from legitimate input.

## Fragmented Benchmarks and Six Open Problems

In Figure 5, “Benchmark coverage heatmap,” the paper rates 7 benchmark families across 7 evaluation capabilities using Strong / Partial / Limited. The strongest areas are RAG/attribution (evidence), tool use, and security attacks. The weakest are cross-component chaining, relation annotation, and recovery-oriented evaluation.

The paper identifies one decisive missing piece: there is **no benchmark that covers evidence labels, tool calls, memory, multi-agent communication, safety, provenance relations, and recovery end to end in an integrated way**.

Section 7 lists six open problems.

1. **Unified trace schemas** — Formats are incompatible across systems, preventing comparison 2. **Semantic and claim-level provenance** — Fine-grained support relations remain difficult 3. **Provenance for memory and multi-agent systems** — Responsibility across sessions and across agents is unclear 4. **Runtime safety and enforcement** — Online provenance for policy compliance remains underexplored 5. **Realistic benchmarks** — Existing datasets lack execution traces 6. **Privacy-preserving audit infrastructure** — Provenance collection itself creates data exposure risks

These six problems amount to a worklist that assigns the opening “process-level accountability gap” to specific components. The paper’s contribution is to distinguish between full execution provenance graphs and their evidence-support projections, organize the trace design space with a six-dimensional taxonomy, map benchmarks onto provenance capabilities, and explicitly identify the gaps in cross-cutting evaluation, relation annotation, and recovery mechanisms. It also publishes a repository for ongoing updates (github.com/xiaoqi-7/Agent-Tracing-Survey).
