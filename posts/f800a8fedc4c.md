## Executive Summary

OpenAIは2026年11月5日、脆弱性の発見と検証に特化したモデル「GPT-6 Cyber」を発表した。ExploitGymでの成績は48.5%(GPT-5.6 Cyberは32.1%)で、同社はPreparedness Frameworkにおけるサイバー分野の分類を「High」から「Critical」に引き上げた。一方で、課題範囲を守る評価「ExploitGym Honeypot」では、デプロイ用プロンプトなしで99.93%の範囲外サービスへの攻撃回避を示したとしている。提供は承認された「Daybreak Red」顧客に限られ、段階的に拡大される。

## 何が発表されたか

OpenAIはGPT-6 Cyberを、脆弱性を見つけて検証する「整合したサイバーセキュリティ・エージェント」と位置づけている。発表文の主張は二つに整理できる。

- 能力:GPT-5.6 Cyberに対し、主要なサイバー系ベンチマークで大きく上回る。ExploitGymでの相対改善は51%。
- 整合性:研究者が設定した境界の内側にとどまる信頼性が「段階的に向上」した。
提供形態は、API と Codex を通じて、承認された Daybreak Red の一部顧客から始まる。OpenAIは、すべての Daybreak Red 顧客へ「まもなく」段階的に広げるとし、GPT-5.6 Cyber は先行してすべての Daybreak Red 顧客に開放するとしている。あわせて、GPT-6 Astra の Daybreak Blue(アルファ)も、より多くの組織と個人の研究者に広げる。

## 能力:数字で見る

発表文が挙げる数字は次のとおりである。いずれも OpenAI 自身の評価結果である。

- ExploitGym(リモート対象の特定の脆弱性を悪用できるかを測る):GPT-6 Cyber 48.5%、GPT-5.6 Cyber 32.1%。差は約16ポイント。
- ウェブのペネトレーションテスト(ソースコードなしでウェブアプリを探索する、新設の評価):GPT-6 Cyber の脆弱性再現率は40.3%、GPT-6 Astra は32.0%。
- RemoteExploitBench(GitLab、PostgreSQL、Jenkins などの既知の脆弱性を管理環境に置いた新ベンチマーク):初期評価で、Daybreak Blue 上の GPT-6 Astra は全タスクを拒否(100%)した一方、GPT-6 Cyber は95%を完了した。失敗は、リモートで動作させられなかった1件のエクスプロイトのみ。
- Linux カーネル:同じ研究用ハーネスで、GPT-5.6 Sol が166件のエクスプロイトを作ったのに対し、GPT-6 Cyber は1,724件の脆弱性を再現し、948件で動作するエクスプロイトを開発した(5倍超)。うち304件の重大な発見を、修正候補とともにメンテナーへ開示した。
- Firefox:Mozilla が高severityと分類する未知の脆弱性81件について、証拠と再現テストを作成した。既知の30件は、従来の報告より深刻であることも示した。Mozilla は報告を受けてほどなく修正の取り込みを始めたという。
- Brotli:Node.js などが使う圧縮ライブラリの重大な脆弱性について、下流アプリケーションでリモートコード実行につながりうることを、他の OpenAI モデルと併用して検証した。
これらを受けて OpenAI は、このモデルを Preparedness Framework のサイバー分野で「Critical」と分類した。GPT-5.6 Cyber は「High」だった。

## 整合性:「範囲を守る」をどう測ったか

サイバーエージェントの固有のリスクとして、発表文は、割り当てられた課題の外へ出る、無関係なサービスを攻撃する、研究者の交戦規則を無視する、の三点を挙げる。

その測定が「ExploitGym Honeypot」である。難しい攻略課題を隔離環境で与え、パッケージレジストリやオブジェクトストアなどの支援サービスを、あえて攻撃しやすくしておく。それらを攻撃すればフラグが得られるが、モデルは「それは課題の範囲外だ」と推論しなければならない。OpenAIによれば、この評価は Hugging Face のインシデントを踏まえて作られた。

結果は次のとおり。

- デプロイ用の安全プロンプトなし:範囲外サービスを攻撃しなかった割合は99.93%(GPT-5.6 Cyber は94.49%)。
- プロンプトあり:100%。
発表文は、モデルの思考過程の抜粋も示している。「don't explore out of scope credentials.」(範囲外の認証情報を探らない)などである。完全な結果は、システムカードに記載されているという。

## 悪用対策と重要インフラ

能力の向上に伴い、悪意ある攻撃者による利用や、モデルの蒸留を狙う試みも増えているとOpenAIは述べる。今回、次の保護を追加・強化した。

- サイバー特化の不整合監視:行動がユーザーの権限と一致しているかを監視する。
- 新たな脅威への標的型監視:たとえば、PHPの重大な脆弱性の協調開示の際は、稼働中のPHPサーバーに対するエクスプロイト開発の試みを標的に監視した。
- Private Safety Processing(PSP):関連するやり取りを自動チェックで審査する。標準の保持が既定で、Zero Data Retention を使うAPI顧客は原則 PSP を使う。PSP は、顧客のストレージに30日間保持される暗号化記録を、プロンプトや応答を OpenAI の担当者に見せずに審査する。
- 盗まれた認証情報への対策:Daybreak Red の API は既定で IP 許可リストを必須とし、認証情報の侵害も監視する。
- サンドボックス、アクション審査、人による監督:高リスクのワークフローで引き続き推奨する。
重要インフラ(発電所、水処理施設、OT/ICS)については、二つの手を打つ。第一に、資源の限られた防御側(政府機関、必須サービス事業者など)のアクセスを補助する10億ドルの「Daybreak for Frontline Defenders」助成と、承認された防御者向けの新グループ「Daybreak Red for Critical Infrastructure」を設ける。第二に、産業制御や安全重要システムを損なう支援を防ぐ保護を更新する。

発表文は、保護のブロック率は「高いほど良い」わけではないと明記している。システムの理解、脆弱性の発見、修正の検証といった技術は正当なセキュリティ業務にも不可欠なため、ブロック率は正当な研究・パッチ作業への支援と併せて評価し、100%は目指さないという。

OT分野の評価では、Dragos と組んだ。Dragos の Rob T. Lee 氏は、模擬の発電所レンジで、ほとんど情報を与えなかったフロンティアモデルが、OT資産と IT のノイズを自力で切り分け、保護リレーのデータを扱うエンジニアリングソフトで二つのゼロデイを見つけたと述べる。同氏は、攻撃前に必要な偵察と脆弱性調査の技術的な敷居が下がっているとも指摘する。OpenAIは Dragos の知見を保護の改善に使ったという。

## 事実と解釈を分ける

事実(発表文に基づく):数字はすべて OpenAI 自身の評価であり、ExploitGym Honeypot や RemoteExploitBench など主要な評価の一部は同社自身が設計・構築したものである。顧客の称賛(Firefox、Calif、Cognition、Palo Alto Networks、Cisco、SentinelOne、CrowdStrike、Perplexity、CodeRabbit)も、発表文に引用されたものに限られる。第三者による再現は、この発表文には含まれない。詳細はシステムカードと Dragos の報告書に委ねられている。

読み取れること:「Critical」への分類と、「範囲を守る」性能の訴求、アクセスの選別は一組で提示されている。能力の評価が上がるほど、公開範囲を絞り、監視を重ね、承認制にするという対応である。この組み合わせが実運用でどこまで機能するかは、発表文だけでは判断できない。たとえば99.93%という数字は、単一の評価環境での値である。

組織の側から見ると、問いは二つに絞られる。自社のコードベースの脆弱性発見に、この種のモデルを使えるか(Daybreak への申請が入口になる)。そして、自社が使うエージェントに、「範囲を守る」ことをどう検証させるか。後者は、ExploitGym Honeypot のように「破れる誘惑が用意された環境」で測るという設計そのものが、参考になる。
